# ТЗ: Доработка страницы товара по эталону Concept 6

Дата: 2026-05-22  
Проект: `C:\Users\sevri\Сайт\elektronom`  
Целевая страница: `/uk/product/[slug]`, `/ru/product/[slug]`  
Пример для проверки: `/uk/product/castrol-edge-5w30-4l`

## 1. Цель задачи

Нужно привести страницу товара к эталонному макету Concept 6 из локально сохраненного дизайна:

```text
C:\Users\sevri\Downloads\карточка товара_files\_bootstrap.html
```

Рабочим эталоном считать локальный экспорт дизайна, а не только live-ссылку Claude, потому что ссылка может требовать активную сессию:

```text
C:\Users\sevri\Downloads\карточка товара_files\_bootstrap.html
C:\Users\sevri\Downloads\карточка товара_files\index-CO1gdLWv.css
```

Если разработчик открывает Claude-ссылку и видит другое состояние, приоритет имеет локальный `_bootstrap.html`, потому что именно он был проанализирован и зафиксирован в этом ТЗ.

Текущая реализация на `https://elektronom.vercel.app/uk/product/castrol-edge-5w30-4l` визуально не принимается как финальная. Разработчику нужно не “примерно сделать три колонки”, а воспроизвести структуру, плотность, пропорции, визуальную иерархию и поведение эталона в рамках существующего Next.js/Tailwind проекта.

## 2. Главный принцип

Страница товара должна выглядеть как рабочая B2B/B2C карточка электротехнического интернет-магазина: плотная, аккуратная, коммерческая, с понятной покупкой, характеристиками, доставкой, оплатой и похожими товарами.

Concept 6 использовать как структурный и композиционный эталон, но визуально страницу нужно адаптировать под уже существующий стиль сайта Электроном:

- общий контейнер, плотность и ширина как на главной и в каталоге;
- коммерческий стиль каталога, а не standalone demo-page;
- синий accent сайта, а не произвольный новый брендовый синий;
- светло-серые панели и белые рабочие карточки как в каталоге;
- те же размеры текста, ритм отступов, border и hover-логика, что в текущих `Header`, `CatalogPage`, `ProductCard`;
- без внедрения чужих шрифтов, палитр, reset CSS или глобального CSS из Claude-макета.

Не делать:

- маркетинговый лендинг;
- большие пустые декоративные секции;
- случайные карточки без структуры;
- “красивую” страницу, которая не повторяет эталон;
- слепую копию Claude CSS с чужими переменными `--ink`, `--brand`, `--line`;
- inline styles вместо Tailwind utility classes;
- хардкод демо-данных вместо реальных данных товара.

## 2.1 Как именно использовать Concept 6

Из Concept 6 нужно взять:

- композицию hero: галерея / покупка / trust-sidebar;
- пропорции desktop hero: `460px / 1fr / 300px`;
- плотную среднюю колонку с брендом, наличием, SKU, ценой, CTA, tier prices, короткими характеристиками;
- dotted separators для коротких характеристик и полной таблицы;
- правый trust sidebar из небольших карточек;
- порядок секций: hero → характеристики → описание/отзывы + похожие товары;
- поведение галереи и thumbnails.

Из Concept 6 нельзя переносить напрямую:

- глобальный `<style>` из `_bootstrap.html`;
- `:root` переменные `--ink`, `--brand`, `--bg`, `--card`;
- шрифты `Manrope` / `JetBrains Mono`, если они не являются частью текущего проекта;
- hardcoded цвета `#2563EB`, `#F4F6FA`, `#0B1220`, `#E6E9EF`;
- классы `.hero`, `.mid`, `.promo-card`, `.spec-list` как отдельный CSS-файл.

Вместо этого реализовать через существующие Tailwind classes и дизайн-токены проекта:

```text
bg-surface-white
bg-surface-alt
bg-surface-raised
text-text-primary
text-text-muted
text-accent
bg-accent-subtle
text-success
bg-success-subtle
text-error
bg-error-subtle
border-border
border-border-strong
rounded-lg / rounded-xl / rounded-2xl
shadow-sm
```

## 2.2 Привязка к текущему стилю главной и каталога

Разработчик должен сверять страницу товара не только с Concept 6, но и с текущими страницами:

```text
/uk
/uk/catalog
/uk/catalog/[slug]
```

Кодовые ориентиры:

```text
src/app/[locale]/page.tsx
src/app/[locale]/(shop)/catalog/page.tsx
src/components/layout/header.tsx
src/components/product/product-card.tsx
src/components/catalog/catalog-sidebar.tsx
src/components/catalog/catalog-hub-tabs.tsx
```

Что сохранить от текущего Электроном-стиля:

- `max-w-[1280px]`;
- page padding `px-4`, на desktop `lg:px-6` или `lg:px-7`;
- основной accent-синий сайта;
- спокойный серый фон страницы;
- белые карточки с тонким border;
- компактные блоки с `text-[11px]`, `text-[12px]`, `text-[13px]`;
- B2B-сигналы: склад, SKU, оптовые цены, оплата для юрлиц, доставка;
- иконки lucide с `strokeWidth={1.5}` или `2`, как в Header/Catalog;
- ProductCard должен оставаться визуально совместим с карточками каталога.

Что не должно появиться:

- отдельная “витринная” страница, визуально оторванная от Header/Catalog;
- слишком большие карточки и пустоты;
- декоративные hero-эффекты, которых нет в каталоге;
- новый набор цветов, который спорит с главной.

## 3. Эталонная структура страницы

### 3.1 Общая ширина и фон

Контейнер страницы:

- max width: около `1280px`;
- центрирование через `mx-auto`;
- горизонтальные отступы как на сайте: mobile `px-4`, desktop `lg:px-6` или `lg:px-7`;
- фон страницы светло-серый: `bg-surface-alt`;
- карточки на белом фоне: `bg-surface-white`;
- border: `border border-border`;
- скругление основных карточек: предпочтительно `rounded-lg`/`rounded-xl`; `rounded-2xl` допустим только если визуально совпадает с текущими catalog blocks и не выглядит чужеродно;
- тень только легкая: `shadow-sm`, без тяжелого “маркетингового” эффекта.

### 3.2 Breadcrumbs

Над товаром должны быть breadcrumbs:

```text
Головна / Каталог / Категорія / Назва товару
```

Требования:

- font size около `12px`;
- muted color;
- текущий товар выделен жирнее;
- ссылки hover в accent color;
- breadcrumbs не должны ломаться на мобильном.

### 3.3 Заголовок товара

Заголовок `h1` должен быть над основной карточкой, как в эталоне.

Требования:

- размер desktop около `26px`;
- font weight `800`;
- line-height плотный, но читаемый;
- не обрезать название товара;
- на mobile не должно быть горизонтального скролла.

## 4. Hero-блок товара

Основная карточка товара должна быть одной белой карточкой, внутри которой на desktop размещена сетка из 3 колонок:

```text
Колонка 1: галерея      ~460px
Колонка 2: покупка      fluid / 1fr
Колонка 3: trust блок   ~300px
```

Рекомендуемый Tailwind:

```tsx
grid grid-cols-1 lg:grid-cols-[minmax(0,460px)_minmax(0,1fr)_300px] gap-5
```

На tablet/mobile:

- все колонки становятся вертикальными;
- порядок сохраняется: галерея → информация/покупка → доставка/гарантии.

## 5. Колонка 1: ProductGallery

### 5.1 Главное изображение

Главное изображение:

- квадратное, `aspect-square`;
- белый фон;
- border `border-border`;
- скругление около `rounded-xl` / `rounded-2xl`;
- товар должен быть `object-contain`;
- не обрезать реальные изображения товаров;
- fallback, если изображений нет.

### 5.2 Placeholder / fallback

Для товаров без фото:

- показывать аккуратный placeholder, а не пустую серую дыру;
- можно использовать иконку или бренд-букву;
- для `https://placehold.co` разрешено `unoptimized`, чтобы не ловить 400 на Vercel;
- `images.prom.ua` должен работать через `next.config.ts`.

### 5.3 Thumbnail strip

Под главным изображением:

- 5 миниатюр в ряд на desktop;
- active thumbnail выделяется accent border и мягким accent shadow;
- миниатюры квадратные;
- если изображений меньше 2, strip можно скрыть;
- клики по миниатюрам меняют главное изображение.

### 5.4 Навигация галереи

Если изображений больше одного:

- стрелка влево;
- стрелка вправо;
- кнопки круглые, белые, с border;
- hover меняет цвет;
- стрелки не перекрывают товар некрасиво.

### 5.5 Lightbox / разворот изображений

Галерея должна работать как полноценная товарная галерея, по поведению близко к примеру:

```text
https://triniti-sb.com.ua/product/videodomofon-7-akuvox-c313n-silver-sip-linux/#gallery-1
```

Функциональные требования:

- клик по главному изображению открывает полноэкранный lightbox/modal;
- в lightbox изображение показывается крупно, без обрезания, `object-contain`;
- фон затемнен, основной сайт под ним не прокручивается;
- есть кнопка закрытия `X`;
- закрытие по `Escape`;
- закрытие по клику на backdrop;
- стрелки `prev/next` внутри lightbox;
- клавиатура: `ArrowLeft`, `ArrowRight`, `Escape`;
- на mobile желательно поддержать swipe left/right;
- показывать счетчик `1 / N`;
- thumbnails должны синхронизироваться с active image;
- при переходе между изображениями active thumbnail должен быть видимым в strip.

Технические требования:

- не использовать отдельный публичный route для галереи;
- не ломать Server Component страницы товара: интерактивность держать внутри `ProductGallery`;
- не добавлять тяжелую carousel-библиотеку без необходимости;
- если нужна библиотека, сначала согласовать и выбирать легкую, например Embla, а не крупный UI-фреймворк;
- все стили через Tailwind classes;
- `next/image` должен корректно работать с `images.prom.ua` и placeholder-URL.

### 5.6 Прокрутка thumbnails

Thumbnail strip должен быть не просто рядом картинок, а управляемая прокрутка:

- desktop: до 5 миниатюр видны сразу;
- если изображений больше 5, strip прокручивается горизонтально;
- добавить маленькие стрелки/градиентные края или аккуратное scroll-snap поведение;
- mobile: горизонтальный scroll с touch;
- active thumbnail: accent border + мягкое выделение;
- thumbnails не должны растягивать hero-card по высоте;
- при смене изображения через стрелки active thumbnail автоматически прокручивается в видимую область.

## 6. Колонка 2: Product Info / Purchase

Колонка должна быть плотной и коммерческой. Не растягивать блоки на большие пустоты.

### 6.1 Brand row

Вверху колонки:

- бренд в отдельной маленькой строке/карточке;
- фон `bg-surface-alt`;
- border `border-border`;
- скругление `rounded-xl`;
- бренд кликабельный, ведет на `/[locale]/brands/[slug]`;
- не показывать пустой бренд-блок, если бренда нет.

### 6.2 Meta row

Ниже:

- статус наличия;
- SKU / код товара.

Состояния:

- `В наявності` / `В наличии` - зеленый;
- `Немає в наявності` / `Нет в наличии` - красный;
- если есть low stock логика, показать “Залишилось N шт” / “Осталось N шт”.

Требования:

- иконка `Check` для наличия;
- иконка `X` для отсутствия;
- SKU в mono/num style;
- без mojibake, текст должен быть читаемый на uk/ru.

### 6.3 Price block

Цена должна быть главным визуальным акцентом средней колонки.

Требования:

- текущая цена около `38px`, `font-extrabold`, `leading-none`;
- старая цена рядом, зачеркнутая;
- скидка показывается маленьким зеленым текстом или badge;
- валюта форматируется через существующий `formatPrice`;
- не ломать формат UAH.

### 6.4 Quantity stepper

На странице товара должен быть выбор количества перед добавлением в корзину.

Требования:

- кнопка минус;
- поле/значение количества;
- кнопка плюс;
- минимум `1`;
- максимум `product.stock`;
- при `stock = 0` степпер и CTA disabled;
- изменение количества не должно дергать layout.

Если текущий `AddToCartButton` не поддерживает количество, нужно доработать API компонента и server action аккуратно, без дублирования логики корзины.

### 6.5 Add to cart CTA

Основная кнопка:

- текст: `Додати в кошик` / `Добавить в корзину`;
- высота около `44px`;
- accent background;
- loading state;
- success state;
- error state;
- disabled state для товара без остатка.

CTA должен реально добавлять выбранное количество товара в корзину, а не быть декоративной кнопкой.

### 6.6 Qty breaks / оптовые цены

Если в `product.attributes.qty_breaks` есть данные, показать таблицу оптовых цен.

Визуально:

- border `border-border`;
- `rounded-xl`;
- header на `bg-surface-alt`;
- 3 колонки: `від, шт` / `ціна за шт` / `знижка`;
- active/current tier можно подсветить accent-soft;
- без inline styles.

### 6.7 Inline key specs

В средней колонке нужно показать короткий список ключевых характеристик, как в эталоне.

Формат:

```text
Номінальний струм ............ 16 A
Кількість полюсів ............ 2
Бренд ........................ Schneider
```

Требования:

- не более 6-8 характеристик;
- dotted separator между ключом и значением;
- ключи должны быть человекочитаемыми, не `rating_a`, а `Номінальний струм, А`;
- если характеристика пустая, не показывать;
- `qty_breaks` не показывать как обычную характеристику.

## 7. Колонка 3: Trust Sidebar

Правая колонка должна быть не случайным набором блоков, а trust/sidebar как в эталоне.

Обязательные карточки:

1. Доставка:
   - иконка `Truck`;
   - текст про Новую почту / курьера / самовывоз.
2. Возврат и обмен:
   - иконка `RotateCcw`;
   - 14 дней.
3. Гарантия:
   - иконка `ShieldCheck`;
   - гарантия производителя, если есть данные, иначе стандартный текст.
4. Оплата для юрлиц:
   - иконка `Package` или `CreditCard`;
   - выделить мягким accent tint `bg-accent-subtle`;
   - текст: оплата на счет, с НДС, для юридических лиц.

Требования:

- каждая карточка: `border border-border rounded-xl p-3`;
- иконка в круге `size-7 rounded-full`;
- заголовок `text-[13px] font-bold`;
- подпись `text-[11px] text-text-muted`;
- высота карточек не должна прыгать от языка ru/uk;
- на mobile блоки идут после покупки.

## 8. Полные характеристики

Полный блок характеристик должен идти сразу под hero-card, на всю ширину.

Требования:

- использовать существующий `ProductAttributes`, но привести его визуально к эталону;
- таблица/список с dotted separators;
- ключ слева, значение справа;
- на desktop ширина ключевой колонки около `280px`;
- на mobile ключ и значение должны оставаться читаемыми;
- не дублировать `qty_breaks`;
- не показывать пустые значения;
- человекочитаемые labels для uk/ru.

## 9. Нижний блок: описание, отзывы, похожие товары

Ниже характеристик:

```text
Левая колонка: описание + отзывы
Правая колонка: похожие товары
```

Рекомендуемый desktop layout:

```tsx
grid grid-cols-1 lg:grid-cols-[minmax(0,1fr)_540px] gap-5
```

### 9.1 Описание

Описание:

- белая карточка;
- title `Опис продукту` / `Описание продукта`;
- аккуратная типографика;
- HTML из БД можно рендерить только если оно приходит из доверенного источника;
- если используется `dangerouslySetInnerHTML`, обязательно проверить, что контент проходит sanitization или источник контролируемый.

### 9.2 Отзывы

Отзывы:

- карточка с title `Відгуки` / `Отзывы`;
- если отзывов нет, показать спокойное empty state сообщение;
- если отзывы есть: avatar circle, имя, дата, stars, текст;
- stars через lucide `Star` или существующие иконки;
- без inline color styles, использовать Tailwind classes.

Дополнительно нужно сделать полноценное визуальное состояние отзывов для приемки:

- средний рейтинг товара над списком, если есть отзывы;
- 5 звезд, заполненные/пустые по rating;
- количество отзывов рядом с рейтингом;
- карточка каждого отзыва:
  - avatar circle или инициалы;
  - имя;
  - дата;
  - stars;
  - текст отзыва;
  - опционально `Переваги` / `Преимущества`;
  - опционально `Недоліки` / `Недостатки`;
- кнопка/ссылка `Залишити відгук` / `Оставить отзыв` как UI-заготовка, если полноценная форма пока не входит в этап.

Важно по данным:

- для production нельзя создавать фейковые отзывы под видом реальных покупателей;
- для staging/dev/visual acceptance нужно добавить seed-отзывы к тестовым товарам, чтобы дизайнерски проверить блок со звездами;
- seed-отзывы должны быть реалистичными, но явно относиться к dev/staging данным;
- если в production у товара нет реальных отзывов, показывать empty state, а не синтетические отзывы.

Минимум для seed/staging:

- 3-5 отзывов на тестовый товар `/uk/product/castrol-edge-5w30-4l`;
- разные рейтинги: 5, 5, 4, 4;
- украинские тексты для `/uk`;
- русские тексты или корректное отображение тех же данных на `/ru`;
- даты в разумном диапазоне;
- не использовать одинаковые имена и одинаковый текст.

Пример структуры visual seed:

```text
Ім'я: Олександр К.
Оцінка: 5
Текст: Швидко відправили, товар відповідає опису. Брав для планового обслуговування.
Переваги: Оригінальна упаковка, нормальна ціна
Недоліки: Не помітив
```

### 9.3 Похожие товары

Похожие товары:

- справа в колонке на desktop;
- на mobile ниже отзывов;
- не показывать текущий товар;
- не ломать страницу, если похожих нет;
- карточки должны быть компактнее, чем основная карточка товара;
- использовать реальные цены, изображения, наличие.

## 10. SEO и structured data

Не сломать существующие SEO-возможности.

Обязательно:

- `generateMetadata`;
- title;
- description без HTML-тегов;
- canonical;
- hreflang uk/ru;
- OpenGraph image;
- `ProductSchema` JSON-LD.

Важно: мета-описание нельзя брать как `description.slice(0, 160)`, если `description` содержит HTML. Нужно чистить HTML-теги.

## 11. Технические ограничения

### 11.1 Next.js 16

Проект на Next.js 16. Перед изменениями читать локальные docs при необходимости:

```text
node_modules/next/dist/docs/
```

Не использовать устаревшие паттерны, которые конфликтуют с Next.js 16 / Cache Components.

### 11.2 Server/Client границы

Страница `/product/[slug]/page.tsx` должна оставаться Server Component.

Client Components допустимы только там, где нужна интерактивность:

- `ProductGallery`;
- quantity stepper, если он клиентский;
- `AddToCartButton`;
- lightbox.

Не превращать всю страницу товара в `'use client'`.

### 11.3 Tailwind v4

Стили должны быть через Tailwind utility classes и существующие дизайн-токены:

- `bg-surface-white`;
- `bg-surface-alt`;
- `bg-surface-raised`;
- `text-text-primary`;
- `text-text-muted`;
- `text-accent`;
- `bg-accent-subtle`;
- `text-success`;
- `bg-success-subtle`;
- `text-error`;
- `bg-error-subtle`;
- `border-border`;
- `border-border-strong`.

Запрещено:

- `style={{ ... }}` для обычного UI;
- hardcoded цвета типа `#fff`, `#F59E0B`, `var(--color-...)` внутри JSX;
- CSS-in-JS для того, что можно сделать Tailwind-классами.

Исключения:

- `dangerouslySetInnerHTML` для JSON-LD в `ProductSchema`;
- контролируемый HTML description, если источник безопасен;
- редкие динамические CSS-переменные только после согласования.

### 11.4 Иконки

Использовать `lucide-react`, не рисовать inline SVG вручную.

Нужные иконки:

- `Check`;
- `X`;
- `Star`;
- `Truck`;
- `RotateCcw`;
- `ShieldCheck`;
- `Package` или `CreditCard`;
- `ChevronLeft`;
- `ChevronRight`;
- `Minus`;
- `Plus`.

## 12. Локализация

Обязательно проверить:

- `/uk/product/[slug]`;
- `/ru/product/[slug]`.

Требования:

- тексты на украинской странице украинские;
- тексты на русской странице русские;
- не должно быть mojibake вида `РџРѕ...`;
- не должно быть смешения языков в одном UI-блоке;
- SEO title/description также локализованы.

## 13. Изображения

Обязательно:

- `images.prom.ua` работает через `remotePatterns`;
- `placehold.co` не ломает Vercel Image Optimization;
- если применяется `unoptimized`, только для placeholder URL;
- реальные CDN-изображения не отключать от оптимизации без причины;
- `alt` берется из `image.alt`, fallback на название товара.

## 14. Адаптивность

Проверить viewport:

- mobile: `390x844`;
- tablet: `768x1024`;
- desktop: `1440x900`;
- wide: `1920x1080`.

На mobile:

- нет горизонтального скролла;
- hero-колонки идут вертикально;
- CTA удобно нажимать;
- цена не вылезает;
- таблицы характеристик не ломают ширину;
- похожие товары уходят ниже.

На desktop:

- 3-колоночный hero выглядит как эталон;
- правая trust колонка не проваливается вниз;
- галерея не растягивает карточку;
- средняя колонка не выглядит пустой.

## 18. Критерии готовности

Задача считается готовой только если:

- страница визуально повторяет эталон Concept 6 по структуре и пропорциям;
- визуальный язык адаптирован под текущие главную и каталог Электронома;
- hero-блок на desktop имеет 3 колонки `460px / 1fr / 300px`;
- галерея, покупка и trust sidebar выглядят как единая карточка;
- галерея имеет thumbnail scroll и полноценный lightbox/разворот изображения;
- quantity stepper работает и учитывает stock;
- Add to cart добавляет выбранное количество;
- полные характеристики идут сразу под hero;
- описание/отзывы/похожие товары расположены ниже в 2-колоночном layout;
- отзывы имеют полноценное состояние со звездами, а для staging/dev добавлены seed-отзывы;
- production не содержит фейковых отзывов под видом реальных;
- нет inline styles в UI страницы товара;
- нет mojibake;
- uk/ru локализация корректна;
- placeholder и CDN-изображения работают;
- lint/typecheck/prisma/build проходят;
- приложены visual screenshots.
