# ЧАСТЬ I. Теория: Verilog как язык черчения электрических схем

## 1.1 Центральный тезис

**Электрическая однолинейная схема ≅ гиперграф + геометрия. Структурный Verilog — каноническая текстовая форма гиперграфа.** Следовательно, Verilog-подмножество может быть *единственным источником истины* чертежа, а холст — лишь его проекцией (view). Это даёт парадигму **Schematic-as-Code**:

```
                ┌────────────── человек (drag&drop) ──────────────┐
                ▼                                                  │
   Verilog (текст)  ──parse──▶  AST  ──elaborate──▶  EngineeringGraph + Drawing  ──render──▶ SVG-холст
                ▲                                                  │
                └──────── export (детерминированный) ◀─────────────┘
                ▲
   LLM-агент (пишет/правит текст)
```

Инвариант системы: **`export(interpret(parse(src)))` стабилен, а `interpret(parse(export(draft))) ≡ draft`** (lossless round-trip). Всё ТЗ построено вокруг защиты этого инварианта.

## 1.2 Почему именно Verilog (а не JSON / собственный DSL)

1. **Изоморфизм модели.** В Verilog: `module` = тип символа из библиотеки, `instance` = узел схемы, `wire`/net = гиперребро, соединяющее N портов, `parameter` = свойства элемента. Это в точности структура `EngineeringGraph` (`graph.ts`). EDA-индустрия (EDIF, SPICE, Verilog netlists) десятилетиями использует netlist как обменный формат схем — мы не изобретаем, а заимствуем проверенную модель.
2. **LLM-прайор.** Verilog массово представлен в обучающих данных моделей. Агент генерирует синтаксически корректный Verilog надёжнее, чем выдуманный DSL, и значительно компактнее (по токенам), чем эквивалентный JSON-граф. Текст диффабелен, версионируем git-ом, читаем человеком при аудите.
3. **Иерархия бесплатно.** `module kitchen_panel(...)` → подсхема (этаж/комната/щит) инстанцируется в корневом модуле. JSON-граф потребовал бы изобретать вложенность; в Verilog она встроена.
4. **Путь к симуляции.** Цифровая часть (управление, АВР-логика) в перспективе прогоняется через iverilog/Verilator; аналоговая семантика (токи, падения напряжения) описывается параметрами в духе Verilog-AMS и считается нашим CAE (`cae.ts`).
5. **Агентная дисциплина.** Текст — идеальный интерфейс «предложи → проверь → примени»: предложение агента компилируется, прогоняется через NormGuard/CAE, и только валидный результат материализуется на холсте. Verilog-источник — это *control/binding layer, not a safety bypass* (как и заявлено в заголовке экспорта).

## 1.3 Три семантических уровня языка (EDL-V — Electronom Drawing Language / Verilog subset)

| Уровень | Носитель в синтаксисе | Что описывает | Потребитель |
|---|---|---|---|
| **L1 Топология** | инстансы + **портовые подключения** `(.L_IN(w1), .L_OUT(w2))` | кто с кем соединён, какими проводниками | граф, NormGuard, BOM |
| **L2 Геометрия** | **атрибуты Verilog-2001** `(* x_mm=100, y_mm=25, rotation=90 *)` и `(* route="(x,y);(x,y)" *)` на wire | где элемент на миллиметровке, как идёт трасса | холст, экспорт PDF/DXF |
| **L3 Физика** | параметры `#(.CURRENT_A(16), .SECTION_MM2(2.5)...)` | электрические величины | CAE, NormGuard, подбор товара |

Ключевое отличие от текущей v2.1: **связность переезжает из комментариев в порты** (D9 закрывается), **геометрия — из комментариев в атрибуты** (легальный синтаксис Verilog-2001, который переживает любые трансформации и парсится стандартными инструментами). Комментарии остаются только для людей.

### Пример целевого синтаксиса v3

```verilog
// Electronom EDL-V v3
(* graph_id="g1", draft_id="d1", canvas="300x200",
   earthing="TT", phase=1, voltage_v=230, locale="uk", name="Квартира 2к" *)
module electronom_project_g1;

  (* conductor="L", route="(75,25);(75,75)" *)  wire L_in_to_mcb1;
  (* conductor="N" *)                            wire N_in_to_mcb1;
  (* conductor="L" *)                            wire L_mcb1_to_kitchen;

  (* x_mm=50,  y_mm=25 *)
  el_grid_input #(.CURRENT_A(32), .LABEL("Ввід")) in_1
    (.L_OUT(L_in_to_mcb1), .N_OUT(N_in_to_mcb1));

  (* x_mm=100, y_mm=75 *)
  el_mcb #(.CURRENT_A(16), .POLES("2P"), .CURVE("C"),
           .PRODUCT_ID("prod-mcb-123"), .SKU("ABB-SH202-C16")) mcb_kitchen
    (.L_IN(L_in_to_mcb1), .N_IN(N_in_to_mcb1), .L_OUT(L_mcb1_to_kitchen));

  (* x_mm=150, y_mm=125 *)
  el_load #(.POWER_W(2000), .AREA_ZONE("dry"), .LABEL("Розетки кухня")) load_kitchen
    (.L_IN(L_mcb1_to_kitchen));

endmodule
```

Узлы получают **портовые сигнатуры** (новое понятие — «библиотека символов»): у `el_mcb` есть `L_IN/L_OUT` (+`N_*` при 2P), у `el_rcd` — `L_IN,N_IN,L_OUT,N_OUT`, у `el_busbar_n` — векторный порт `N_TAPS[0..n]` и т.д. Сигнатура одновременно = точки подключения (pin) на SVG-символе → трассировщик знает, откуда выходит провод.

## 1.4 Агент рисует Verilog-ом: модель взаимодействия

Два равноправных интерфейса, сводящихся к одному типу операции — **патч графа**:

1. **Декларативный (основной для LLM):** агент получает текущий source + задачу («добавь группу УЗО на ванную»), возвращает новый source целиком или unified-diff. Pipeline: `parse → elaborate → NormGuard/CAE → preview → apply`. Ошибки парсера/нормоконтроля возвращаются агенту для самокоррекции (compile-fix loop, до N итераций).
2. **Императивный (MCP / tool-calls):** уже задекларированный `mcpControlManifest` (`verilog-exporter.ts:148-158`) превращается в реальные инструменты: `place_node`, `move_node`, `connect_edge`, `set_node_property`, `bind_catalog_product`, `route_edge`, `generate_from_brief`. Каждый tool внутри редактирует draft и регенерирует Verilog — текст и холст никогда не расходятся.

«Мастер автогенерации» из `calculator_cad_concept.md` — частный случай №1: форма калькулятора → промпт/шаблон → Verilog → холст. Существующий калькулятор (`calculators.ts`) становится детерминированным генератором того же языка — то есть **калькулятор, агент и человек пишут на одном языке**, и NormGuard судит всех одинаково.

## 1.5 Формальная грамматика (EBNF, ядро)

```ebnf
source       = { pragma | comment }, module ;
pragma       = "(*", attr, { ",", attr }, "*)" ;
attr         = ident, [ "=", ( number | string ) ] ;
module       = "module", ident, ";", { item }, "endmodule" ;
item         = wire_decl | instance | comment ;
wire_decl    = [ pragma ], "wire", ident, { ",", ident }, ";" ;
instance     = [ pragma ], module_type, [ param_block ], ident, port_block, ";" ;
module_type  = "el_", ident ;
param_block  = "#(", named_param, { ",", named_param }, ")" ;
named_param  = ".", IDENT_UPPER, "(", ( number | string ), ")" ;
port_block   = "(", [ named_port, { ",", named_port } ], ")" ;
named_port   = ".", ident, "(", [ ident ], ")" ;
```

Свойства: однопроходный детерминированный разбор, восстановление после ошибок на границе `;`, каждая ошибка с номером строки (уже есть в `VerilogParseError`). Пустой `port_block` остаётся валидным → обратная совместимость с v2.1-источниками (тогда связность берётся из legacy-комментариев `// edge`).

    index.ts            ← pipeline

## 2.2 Тест-план

1. **Property-тест инварианта** (F0.7): random draft → export → parse → interpret → deep-equal (исключая `updatedAt`). ≥1000 кейсов в CI.
2. **Golden-файлы:** 5 эталонных схем (1ф квартира, 3ф дом, генератор+АВР, солнечная с DC, щит с УЗО-каскадом) — экспортированный source фиксируется, диффы ревьюятся.
3. **Adversarial-сьют** — `scripts/test-verilog-edge-cases.ts` (создан в рамках аудита, 8 кейсов) переносится в vitest.
4. **Agent-eval:** 20 текстовых брифов («2к квартира, бойлер, кондиционер...») → агент → компиляция без ошибок ≥90%, NormGuard-критичных нарушений 0.
5. **E2E (gstack/playwright):** холст: генерация мастером, drag узла, compile из textarea, save/load, схема→корзина.

## 2.3 Безопасность и нормоконтроль

- Verilog-source — **никогда не безопасность**: любые проверки выполняет только NormGuard/CAE после elaboration; агент не может «отключить» правило текстом.
- Лимиты: source ≤200КБ, ≤500 узлов, ≤2000 wire; таймаут компиляции; парсер без `eval`/`new Function`.
- Агентский вывод применяется только после успешной компиляции и показа diff пользователю (человек — финальный аппрувер схемы).
- В промпт агента не попадают server-секреты; каталожные данные — через tool с `select` (без cost price).

## 2.4 Риски

| Риск | Митигация |
|---|---|
| LLM генерирует невалидный синтаксис | compile-fix loop + few-shot + грамматика в промпте; фолбэк на императивные MCP-tools |
| Расхождение текста и холста | единственный путь мутации — патч draft + регенерация source (никаких прямых правок текста UI-ом, кроме textarea с явной компиляцией) |
| Несовместимость v2.1 ↔ v3 | парсер v3 принимает v2.1; экспорт только v3; миграция сохранённых черновиков при load |
| Раздувание токенов на больших схемах | иерархия (F1.5): агенту отдаётся только редактируемый подмодуль |

## 2.5 Открытые вопросы (для решения до Фазы 3/4)

4. Мобильный UX холста: read-only просмотр или полное редактирование?
5. Лимит проектов на пользователя / монетизация (PRO-тариф за DXF/историю ревизий)?
