Дата: 2026-05-22  
Проект: `C:\Users\sevri\Сайт\elektronom`

Целевая страница: `/uk/product/[slug]`, `/ru/product/[slug]`  
Проверочный URL: `/uk/product/castrol-edge-5w30-4l`

## 1. Цель

По визуальной приемке страницы товара выделены 3 недоработанные зоны:

1. `Інші товари тієї ж серії`
2. `Відгуки покупців`
3. `Супутні товари`

Эти блоки сейчас выглядят как черновые вставки: не хватает выравнивания, коммерческой плотности, единого стиля Электронома, нормальных состояний и аккуратной адаптивности.

Нужно довести их до уровня готовой e-commerce страницы, совместимой с главной, каталогом и карточками товаров.

## 2. Общие правила для всех трех блоков

### 2.1 Визуальный стиль

Использовать визуальный язык текущего сайта Электроном:

- `max-w-[1280px]`;
- белые карточки `bg-surface-white`;
- фон страницы `bg-surface-alt`;
- тонкие границы `border border-border`;
- легкие скругления `rounded-lg` / `rounded-xl`;
- мягкая тень только при необходимости `shadow-sm`;
- compact UI: `text-[11px]`, `text-[12px]`, `text-[13px]`;
- основной accent color сайта;
- `lucide-react` иконки;
- ProductCard/каталог как ориентир для карточек товаров.

Не использовать:

- inline styles `style={{ ... }}`;
- hardcoded цвета типа `#fff`, `#2563EB`, `#F59E0B`;
- чужой CSS из Claude design;
- декоративные большие карточки;
- пустые блоки без данных;
- mojibake-тексты вида `Рџ...`, `Рќ...`;
- фейковые production-отзывы под видом реальных.

### 2.2 Адаптивность

Проверить:

- desktop `1440x900`;
- wide desktop `1920x1080`;
- tablet `768x1024`;
- mobile `390x844`.

На mobile:

- все красные зоны должны быть full-width;
- не должно быть горизонтального скролла страницы;
- допускается горизонтальный scroll внутри товарных каруселей;
- кнопки корзины должны быть нажимаемыми;
- текст не должен налезать на цену или иконки.

### 2.3 Компонентность

Рекомендуется вынести/доработать отдельные компоненты:

```text
src/components/product/same-series-products.tsx
src/components/product/product-reviews.tsx
src/components/product/related-products-section.tsx
src/components/product/compact-product-row.tsx
src/components/product/compact-product-card.tsx
```

Если компоненты уже есть, не плодить дубли, а привести существующие к требованиям.

## 3. Блок `Інші товари тієї ж серії`

## 3.1 Назначение

Блок должен помогать пользователю быстро выбрать альтернативу из той же серии/линейки товара: другой номинал, вариант, модель, цвет, комплектацию.

Это не “похожие товары вообще”, а именно близкие варианты текущего товара.

## 3.2 Источник данных

Приоритет источников:

1. Явная серия/линейка товара, если есть в данных.
2. Общий бренд + категория + похожий slug/name/model.
3. Общая категория + совпадающие ключевые атрибуты.

Не показывать:

- текущий товар;
- неактивные товары;
- товары без цены;
- товары, которые нельзя открыть по slug.

Если данных для серии нет, блок скрыть или заменить на аккуратный empty state только в dev/staging. На production лучше скрыть.

## 3.3 Layout desktop

Блок расположен в правой колонке рядом с описанием, как на текущем скрине, но должен выглядеть как законченный commercial list.

Карточка блока:

- `bg-surface-white border border-border rounded-xl`;
- header:
  - title `Інші товари тієї ж серії` / `Другие товары этой серии`;
  - справа маленькая ссылка/иконка `Всі` / `Все`, если товаров больше видимых;
- body: вертикальный список compact rows;
- footer: кнопка `Всі товари` / `Все товары`, если есть больше 4-5 позиций.

## 3.4 Compact row товара

Каждая строка:

```text
[фото 56x56] [название 2 строки + SKU/наличие] [qty?] [цена] [cart icon]
```

Требования:

- высота строки стабильная, около `78-90px`;
- фото слева, квадрат `56x56` или `64x64`;
- изображение `object-contain`;
- fallback, если фото нет;
- название максимум 2 строки, `line-clamp-2`;
- SKU/артикул мелким mono/num;
- статус наличия маленьким зеленым/красным текстом;
- цена выровнена по правому краю;
- кнопка корзины всегда в одном месте;
- hover всей строки: мягкий `bg-surface-alt`;
- строки разделены `border-b border-border`, кроме последней;
- весь title/фото кликабельны на страницу товара.

## 3.5 Quantity в этом блоке

Если нужен stepper в `Інші товари тієї ж серії`, он должен быть очень компактным.

Допустимые варианты:

1. Только cart icon добавляет `1` товар.
2. Мини-stepper `[-] [1] [+]` шириной не более `84px`.

Не делать широкий stepper, который ломает строку.

## 3.6 Mobile

На mobile блок:

- идет после основного hero или после описания, по согласованному порядку;
- full-width;
- строки остаются строками, не превращаются в огромные карточки;
- если тесно, цена и cart icon уходят во вторую строку внутри row, но без хаоса.

## 3.7 Acceptance

Блок принимается, если:

- выглядит как законченный список альтернатив;
- элементы ровно выровнены;
- нет текущего товара в списке;
- кнопки корзины работают;
- блок не выглядит как случайная узкая вставка;
- на mobile не ломается.

## 4. Блок `Відгуки покупців`

## 4.1 Назначение

Блок должен повышать доверие и показывать социальное доказательство, но не должен имитировать реальные отзывы, если их нет.

Для production:

- показывать только реальные отзывы;
- если отзывов нет, показывать empty state.

Для dev/staging:

- разрешено добавить seed-отзывы для визуальной приемки;
- seed-отзывы должны быть тестовыми данными, не выдавать их за реальные production-отзывы.

## 4.2 Layout desktop

Отзывы должны быть одним цельным блоком, а не двумя визуально несвязанными частями.

Рекомендуемый desktop layout:

```text
Card: Відгуки покупців
├─ Header: title + button "Написати відгук"
├─ Body grid:
│  ├─ Left rating summary card, width 240-280px
│  └─ Right reviews list, fluid
```

Общая карточка:

- `bg-surface-white border border-border rounded-xl p-5`;
- title `Відгуки покупців` / `Отзывы покупателей`;
- кнопка `Написати відгук` / `Написать отзыв` справа в header;
- кнопка secondary/accent, не слишком яркая.

## 4.3 Rating summary

Левая карточка рейтинга:

- большой рейтинг, например `4.7`;
- 5 звезд под числом;
- подпись `на основі N відгуків`;
- breakdown по 5/4/3/2/1 звездам;
- bars должны быть аккуратными, с одинаковой шириной;
- фильтры/чипы:
  - `Всі`;
  - `З фото`;
  - `Позитивні`;
  - `Критичні`;
- если фильтры пока не работают, не делать их интерактивными или явно реализовать состояние.

Не оставлять карточку пустой или слишком оторванной от списка.

## 4.4 Reviews list

Каждый отзыв:

```text
[avatar/initial] Имя + verified badge + date
★★★★★
Текст отзыва
Переваги: ...
Недоліки: ...
```

Требования:

- avatar circle с инициалом или фото;
- имя;
- дата;
- badge `Підтверджена покупка` / `Подтвержденная покупка`, если есть основание;
- 5 звезд, заполненные по `rating`;
- текст отзыва `text-[13px]` / `text-sm`;
- разделение отзывов через border или отдельные soft cards;
- max-height со scroll допустим, но scrollbar должен быть аккуратным;
- не обрезать отзыв слишком агрессивно;
- если отзывов много, добавить `Показати ще`.

## 4.5 Empty state

Если отзывов нет:

- title блока остается;
- показывается спокойный empty state:
  - `Поки немає відгуків`;
  - `Будьте першим, хто залишить відгук`;
  - кнопка `Написати відгук`;
- не показывать рейтинг `0.0` как будто это плохая оценка.

## 4.6 Seed отзывы для staging/dev

Для проверки дизайна добавить seed-данные:

- минимум 4 отзыва;
- рейтинги: `5`, `5`, `4`, `4`;
- разные имена;
- разные даты;
- разная длина текста;
- минимум один отзыв с преимуществами/недостатками;
- тексты должны быть нормальными украинскими/русскими, без mojibake.

Пример:

```text
Ім'я: Олександр К.
Оцінка: 5
Дата: 2026-05-10
Текст: Швидко відправили, товар відповідає опису. Брав для планового обслуговування.
Переваги: Оригінальна упаковка, нормальна ціна
Недоліки: Не помітив
```

## 4.7 Форма отзыва

Если полноценная отправка отзывов не входит в этап:

- кнопка `Написати відгук` может открывать disabled/modal placeholder;
- в отчете явно написать, что форма отправки отзывов не реализована.

Если входит в этап:

- rating select;
- textarea;
- имя/email для гостя или авторизованный user;
- server action;
- валидация;
- moderation status, чтобы отзывы не публиковались сразу без проверки.

## 4.8 Acceptance

Блок принимается, если:

- выглядит как цельная секция;
- rating summary визуально связан со списком;
- звезды корректно отражают рейтинг;
- seed/staging отзывы отображаются реалистично;
- production не содержит фейковые отзывы;
- empty state аккуратный;
- mobile layout не ломается.

## 5. Блок `Супутні товари`

## 5.1 Назначение

Блок должен продавать аксессуары, расходники, совместимые товары или часто покупаемые вместе позиции.

Это отдельная зона cross-sell, не дубль `Інші товари тієї ж серії`.

## 5.2 Источник данных

Приоритет:

1. Явные related/accessory links, если есть.
2. Товары из связанных категорий.
3. Товары того же бренда/категории, но не текущий товар.
4. Fallback: популярные товары категории.

Не показывать:

- текущий товар;
- товары без slug;
- неактивные товары;
- пустые карточки.

## 5.3 Layout desktop

Секция full-width ниже отзывов/описания или в нижней зоне страницы.

Header:

- title `Супутні товари` / `Сопутствующие товары`;
- справа ссылка `Дивитися всі` / `Смотреть все`, если применимо.

Grid:

- desktop: 4 карточки в ряд;
- wide desktop: можно 4, не растягивать до 5, если карточки становятся пустыми;
- tablet: 3 карточки;
- mobile: 2 колонки или горизонтальный scroll, выбрать один паттерн и сделать аккуратно.

## 5.4 Карточка сопутствующего товара

Карточка должна быть совместима со стилем ProductCard каталога.

Требования:

- одинаковая высота карточек;
- `bg-surface-white border border-border rounded-lg`;
- image container стабильный, примерно `aspect-square` или фиксированная высота;
- изображение `object-contain`, не мелкое и не потерянное в пустоте;
- badge `Рекомендовано` / `Рекомендовано` маленький, не кричащий;
- название максимум 2 строки;
- SKU/бренд мелко;
- наличие;
- цена внизу;
- cart button в одном месте;
- hover state;
- если нет фото, аккуратный fallback;
- кнопка корзины реально добавляет товар.

## 5.5 Проблемы, которые нужно убрать

Не должно быть:

- огромных пустых зон вокруг фото;
- разного положения цен;
- разного положения cart buttons;
- карточек разной высоты;
- слишком ярких оранжевых бейджей, которые спорят с accent сайта;
- визуального ощущения “заготовки”.

## 5.6 Mobile

На mobile:

- 2 колонки, если карточки помещаются без тесноты;
- или горизонтальная карусель с `snap-x`;
- кнопки не должны быть меньше удобного touch target;
- названия не должны ломать сетку.

## 5.7 Acceptance

Блок принимается, если:

- карточки выглядят как часть каталога;
- товары коммерчески понятны;
- все карточки ровные;
- изображения, цена, наличие и cart button выровнены;
- mobile не ломается;
- нет дублирования текущего товара.

## 6. Галерея товара: обязательное усиление

В рамках этой доработки также проверить галерею товара, потому что она влияет на восприятие всей страницы.

Требования:

- thumbnail strip с горизонтальной прокруткой, если фото больше 5;
- active thumbnail всегда видим;
- клик по главному фото открывает lightbox;
- в lightbox есть:
  - затемнение фона;
  - крупное изображение;
  - `X`;
  - стрелки;
  - `Escape`;
  - закрытие по backdrop;
  - счетчик `1 / N`;
  - mobile swipe желательно;
- поведение ориентировать на обычные e-commerce галереи, например:

```text
https://triniti-sb.com.ua/product/videodomofon-7-akuvox-c313n-silver-sip-linux/#gallery-1
```

## 7. Проверки перед сдачей

Команды:

```powershell
npm run lint
npx tsc --noEmit
npx prisma validate
npm run build
```

Важно: `npm run lint` должен проходить для проекта целиком. Формулировка `pass, excluding scratch` не принимается. Если `scratch` остается в проекте, его нужно либо удалить, либо корректно исключить из lint/репозитория согласованным способом.

Поисковые проверки:

```powershell
rg -n "style=\{|style=" "src/app/[locale]/(shop)/product/[slug]/page.tsx" src/components/product src/components/cart
rg -n "Рџ|Рќ|Р”|Рљ|Рћ|Р’ РЅ" "src/app/[locale]/(shop)/product/[slug]/page.tsx" src/components/product src/components/cart src/actions src/i18n
```

Ожидание:

- inline styles в UI этих блоков отсутствуют;
- mojibake отсутствует;
- если есть `dangerouslySetInnerHTML`, разработчик объясняет источник и безопасность.

## 10. Критерии готовности

Задача считается готовой только если:

- все 3 красные зоны выглядят как финальный e-commerce UI;
- `Інші товари тієї ж серії` работает как аккуратный список альтернатив;
- `Відгуки покупців` имеет рейтинг, звезды, список отзывов и empty state;
- seed-отзывы есть только для staging/dev;
- `Супутні товари` выглядит как полноценная товарная витрина;
- галерея имеет lightbox и прокрутку thumbnails;
- нет inline styles;
- нет mojibake;
- lint/typecheck/prisma/build проходят;
- приложены desktop/mobile скриншоты всех зон.
