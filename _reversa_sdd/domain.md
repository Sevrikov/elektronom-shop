# Домен и бизнес-правила — Elektronom

> Артефакт агента **Detective** (Фаза 3 — Интерпретация) · Reversa · `doc_level=completo` · Язык: Русский
> Источники: код (`code-analysis.md`, `modules.json`, `data-dictionary.md`) + git-история. Уверенность: 🟢 подтверждено · 🟡 выведено · 🔴 пробел.

## 1. Что это за система

**Elektronom** — интернет-магазин **электротехники и автотоваров** (украинский рынок, B2C + признаки B2B). Ассортимент: автоматические выключатели, розетки/выключатели, кабель, моторные масла, аккумуляторы/ИБП, LED-освещение. Особенности: мультиязычность (uk/ru), динамические характеристики товаров (фасеты), AI-консультант по подбору оборудования, интеграция с внешними поставщиками (ASKO) и «контент-фабрикой».

## 2. Глоссарий предметной области

| Термин | Значение | Где в коде |
|--------|----------|-----------|
| **SKU** | Уникальный артикул товара (`Product.sku @unique`) | `Product` |
| **MPN** | Manufacturer Part Number (артикул производителя) | `SupplierInventory.mpn` |
| **Фасет (facet)** | Динамическая характеристика для фильтрации (poles, section, viscosity…), хранится в JSONB `Product.attributes` | `catalog` |
| **Реактивный счётчик** | Кол-во товаров у опции фильтра с учётом всех *других* активных фильтров (приём «exclude self») | `getCategoryFacets` |
| **Quick links** | SEO/UX-чипы под H1 категории (готовые фильтры/лендинги) | `catalog-filter-config` |
| **qty break / qty_breaks** | Оптовая ценовая ступень (от кол-ва → скидка %) | `product` (JSONB `attributes.qty_breaks`) |
| **Наличие (inStock)** | `stock > 0` | сквозное |
| **Снапшот (snapshot)** | Замороженная копия данных на момент заказа (`customerData`, `OrderItem.snapshot`) | `orders` |
| **Идемпотентность** | Защита от двойного создания заказа по `idempotencyKey` | `createOrder` |
| **Премодерация** | Отзыв виден только после одобрения (`isVisible=false` по умолчанию) | `product`/`admin` |
| **verifiedPurchase** | Отзыв от пользователя с доставленным (`DELIVERED`) заказом товара | `submitProductReview` |
| **Регидратация** | Подмена данных от LLM на реальные из БД (цена/наличие) | `assistant` |
| **Контент-фабрика** | Внешний сервис AI-генерации описаний товаров | `admin` (Content Factory) |
| **Workload** | Индикатор загруженности магазина по числу активных заказов | `queries/workload.ts` 🟡 |
| **locale** | Язык контента: `uk` (default) или `ru` | сквозное (i18n) |

## 3. Бизнес-правила (консолидированно)

### 3.1 Каталог и фильтрация
- **BR-CAT-1** 🟢 Видны только `isActive` товары и категории.
- **BR-CAT-2** 🟢 Фильтр атрибутов: **AND между ключами, OR внутри ключа**.
- **BR-CAT-3** 🟢 `priceMin > priceMax` → значения меняются местами.
- **BR-CAT-4** 🟢 Любое изменение фильтра сбрасывает пагинацию (`page=1`).
- **BR-CAT-5** 🟢 Опция фасета `disabled`, если её счётчик = 0 и она не выбрана.
- **BR-CAT-6** 🟢 Счётчики фасетов реактивны (учитывают все фильтры, кроме своей группы).
- **BR-CAT-7** 🟡 Сортировка значений — `localeCompare(numeric)` (корректный порядок «2.5» < «10»).
- **BR-CAT-8** 🟢 Дерево категорий строится из плоского списка по `parentId`.

### 3.2 Товар и отзывы
- **BR-PR-1** 🟢 `comparePrice` показывается только если строго больше `price` (расчёт скидки `getDiscountPercent`).
- **BR-PR-2** 🟢 Один отзыв на пару пользователь+товар (`@@unique[productId,userId]`).
- **BR-PR-3** 🟢 Отзыв создаётся скрытым (`isVisible=false`), показ — после модерации админом.
- **BR-PR-4** 🟢 `verifiedPurchase` = есть `DELIVERED`-заказ с этим товаром.
- **BR-PR-5** 🟢 Валидация отзыва: `rating` 1–5, `comment` 1–1000, плюсы/минусы ≤500.
- **BR-PR-6** 🟡 Оптовые цены (`qty_breaks`): цена = `base × (1 − discount/100)`.

### 3.3 Корзина
- **BR-CART-1** 🟢 Гость — корзина в httpOnly-cookie (30 дней); авторизованный — в БД (`CartItem`).
- **BR-CART-2** 🟢 При входе гостевая корзина сливается в БД (`qty = min(existing+new, stock, 99)`), cookie очищается.
- **BR-CART-3** 🟢 Количество ограничено `1..99` и не больше `stock`.

### 3.4 Заказы (инварианты — критично)
- **BR-ORD-1** 🟢 **Идемпотентность:** при повторе с тем же `idempotencyKey` возвращается существующий заказ (не создаётся новый).
- **BR-ORD-2** 🟢 **Сток не уходит в минус:** списание условным `updateMany (stock ≥ qty)`; при недостатке — откат транзакции с ошибкой.
- **BR-ORD-3** 🟢 **Номер заказа** уникален и последователен по годам: `ORD-YYYY-NNNNN` (через `OrderCounter` внутри транзакции).
- **BR-ORD-4** 🟢 Заказ хранит **снапшоты** покупателя и позиций → неизменен при изменении/удалении товара.
- **BR-ORD-5** 🟢 Заказ виден только владельцу (`order.userId === userId`); гость — по 5-мин cookie `last_created_order`.
- **BR-ORD-6** 🟡 `shipping=0`, `discount=0` — доставка и промокоды пока не рассчитываются.
- **BR-ORD-7** 🔴 Онлайн-оплата (`CARD_ONLINE`) не инициируется при оформлении — `paymentStatus` остаётся `PENDING`.

### 3.5 Аутентификация и доступ
- **BR-AUTH-1** 🟢 Пароль ≥6 символов; хранится bcrypt (cost 10).
- **BR-AUTH-2** 🟢 Смена пароля недоступна для OAuth-аккаунтов (нет `passwordHash`).
- **BR-AUTH-3** 🟢 Email уникален; повторная регистрация запрещена.
- **BR-AUTH-4** 🟢 Роли: `CUSTOMER`/`MANAGER`/`ADMIN`; админ-действия требуют `ADMIN`.
- **BR-AUTH-5** 🔴 Нет верификации email и авто-логина после регистрации.

### 3.6 AI-ассистент
- **BR-AS-1** 🟢 Длина сообщения ≤800; история усекается до 10 последних.
- **BR-AS-2** 🟢 Блокировка попыток prompt-injection (regex).
- **BR-AS-3** 🟢 Цены/наличие в ответе берутся из БД (регидратация), не из LLM.
- **BR-AS-4** 🟡 Rate limit: не чаще 1 сообщения / 2 c с одного IP.
- **BR-AS-5** 🔴 «Источники» (sources) — захардкоженные плейсхолдеры, не реальные документы.

### 3.7 Контент и поиск
- **BR-IDX-1** 🟢 При деактивации товара он удаляется из индекса Algolia; иначе апсертится в `products_uk`/`products_ru`.
- **BR-IDX-2** 🟢 Поиск деградирует на Prisma при недоступности Algolia.
- **BR-CF-1** 🟡 Контент-фабрика генерирует описания товаров через внешний сервис (admin).

## 4. Сквозные инварианты данных
- **INV-1** 🟢 Денежные значения — `Decimal(12,2)` (без float-погрешностей).
- **INV-2** 🟢 Локализуемый контент в `*Translation` (uk/ru); бренд — единое имя.
- **INV-3** 🟢 Удаление сущностей каскадно/SetNull сохраняет целостность (заказ переживает удаление товара через снапшот).
- **INV-4** 🔴 `qty_breaks`, `Address`, `SupplierInventory`, embedding-RAG — присутствуют в модели, но частично/не используются в рантайме.
