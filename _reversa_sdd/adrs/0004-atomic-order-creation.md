# ADR-0004 — Атомарное создание заказа: идемпотентность, нумерация, безопасное списание стока

**Статус:** Принято · 🟢 подтверждено кодом (сильная сторона)

## Контекст
Оформление заказа должно быть устойчиво к двойному сабмиту, конкурентному списанию остатков и коллизиям номеров.

## Решение
`createOrder` выполняет всё в `prisma.$transaction`:
1. **Идемпотентность** — предпроверка `idempotencyKey @unique`; при повторе возвращается существующий заказ.
2. **Списание стока без ухода в минус** — `updateMany where {id, stock ≥ qty} decrement`; `count===0` → throw → откат (оптимистичная блокировка).
3. **Номер** — `OrderCounter.upsert({year}) increment` → `ORD-YYYY-NNNNN` (внутри транзакции, без коллизий).
4. Создание `Order`+`OrderItem` со снапшотами; очистка корзины в той же транзакции.

## Последствия
- ➕ Корректность под конкуренцией, отсутствие oversell, последовательные номера.
- ➕ Защита от дублей заказов.
- ➖ Цикл `updateMany` по позициям — N запросов в транзакции (приемлемо для типовых корзин).
- ➖ Онлайн-оплата не интегрирована в этот поток (🔴 BR-ORD-7).
