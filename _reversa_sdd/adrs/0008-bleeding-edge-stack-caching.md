# ADR-0008 — Стек «bleeding edge» и кэширование `'use cache'`

**Статус:** Принято · 🟢 подтверждено (`package.json`, код запросов)

## Контекст
Проект стартовал на самых свежих версиях экосистемы Next/React/Prisma для использования RSC, React Compiler и нового кэширования.

## Решение
- **Next.js 16 + React 19 + React Compiler + Prisma 7 + NextAuth 5-beta + Tailwind 4.**
- Кэширование данных через директиву **`'use cache'`** с `cacheLife` (seconds/minutes/hours) и `cacheTag` для точечной инвалидации (`revalidateTag`).
- Профиль кэша: категории — `hours`, фасеты — `minutes`, товар — `seconds`, список товаров (по URL) — **без кэша**; персональные данные (заказы) — без кэша.
- Изображения: абстракция хранилища (Cloudinary в проде, локально только в dev).

## Последствия
- ➕ Современный DX, гранулярная инвалидация, серверные компоненты.
- ➖ **Риск нестабильности** (beta/новые мажоры), мало community-практик (🟡 системный риск из `dependencies.md`).
- ➖ `prisma`/`shadcn` в `dependencies` (а не dev) — раздувает прод-зависимости.
- ➖ Отсутствие тест-раннера усиливает риск регрессий на таком стеке (🔴).
