# ADR-0001 — Динамические характеристики товара через JSONB `attributes`

**Статус:** Принято (ретроспективно зафиксировано Reversa) · 🟡 выведено из кода

## Контекст
Категории магазина имеют разные наборы характеристик (автоматы: полюса/ток/кривая; кабель: тип/жилы/сечение; масла: вязкость/объём). Жёсткая реляционная схема под каждую категорию негибка.

## Решение
Хранить характеристики в одном поле `Product.attributes Json` (JSONB) + конфиги фильтров на уровне приложения (`catalog-filter-config.ts`, `categoryFilters`). Поиск по атрибутам — через JSON-path в Postgres (`buildAttributeWhere`), ускорен GIN-индексом (`add_product_attributes_gin_index`).

## Последствия
- ➕ Гибкость: новая категория/характеристика без миграции схемы.
- ➕ Один индекс GIN покрывает все атрибуты.
- ➖ Нет типобезопасности значений (строки/числа смешаны) → нужна нормализация в коде (источник риска C-2/C-6).
- ➖ Агрегация фасетов по JSONB сложна → привела к in-memory расчёту (см. [ADR-0002](0002-in-memory-reactive-facets.md)).

## Альтернативы
EAV-таблица (сложные джойны), отдельные колонки на категорию (миграции), отдельная таблица атрибутов с типами (оверинжиниринг для MVP).
