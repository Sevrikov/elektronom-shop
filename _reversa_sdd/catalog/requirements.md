# Требования — модуль `catalog`

> SDD-спецификация (Writer, `completo`, hybrid) · Reversa · Язык: Русский
> Уверенность: 🟢 подтверждено · 🟡 выведено · 🔴 лакуна. Источник: `code-analysis.md` §catalog, `domain.md`.

## Назначение
Просмотр каталога: дерево категорий, страница категории с динамическими фасетными фильтрами и реактивными счётчиками, листинг товаров с пагинацией/сортировкой, бренды.

## Функциональные требования (MoSCoW)

### Must
- **FR-CAT-1** 🟢 Отображать только активные (`isActive`) категории и товары.
- **FR-CAT-2** 🟢 Страница категории `/[locale]/catalog/[slug]`: H1, дерево/подкатегории, листинг, сайдбар фильтров.
- **FR-CAT-3** 🟢 Фильтрация по бренду (мульти), цене (диапазон), наличию и **динамическим атрибутам** (JSONB): AND между ключами, OR внутри ключа.
- **FR-CAT-4** 🟢 **Реактивные счётчики** опций фасетов (учёт всех фильтров, кроме своей группы); опция `disabled` при count=0 и не выбрана.
- **FR-CAT-5** 🟢 Пагинация (24/стр) и сортировка (`popular|price-asc|price-desc|new|rating`).
- **FR-CAT-6** 🟢 Состояние фильтров — в URL (каноничный порядок параметров); сброс `page` при изменении фильтра.

### Should
- **FR-CAT-7** 🟢 Гистограмма цен (32 бакета) для слайдера диапазона.
- **FR-CAT-8** 🟢 Per-category конфиг фильтров (порядок, лейблы uk/ru, единицы, searchable, quickLinks).
- **FR-CAT-9** 🟢 Хлебные крошки и мегаменю/дерево навигации.

### Could
- **FR-CAT-10** 🟡 Quick links (SEO/UX-чипы) под H1.

### Won't (в текущем виде)
- **FR-CAT-11** 🔴 SQL-агрегация фасетов (пока in-memory); вынос в Algolia.

## Нефункциональные требования
- **NFR-CAT-1 (Performance)** 🟢 Кэширование: категории/дерево — `cacheLife('hours')`, фасеты — `minutes`; список — без кэша (динамика по URL). GIN-индекс по `attributes`.
- **NFR-CAT-2 (Scalability)** 🔴 Расчёт фасетов ограничен 50 000 товаров на категорию (in-memory) — узкое место.
- **NFR-CAT-3 (i18n)** 🟢 Контент по `locale` (uk/ru) из `*Translation`.

## Критерии приёмки

**AC-CAT-1 — фильтрация по атрибуту (happy)** 🟢
- Дано: категория «avtomatychni-vymykachi» с товарами разных `poles`.
- Когда: пользователь выбирает `poles=1P,2P`.
- Тогда: показываются товары с `poles ∈ {1P,2P}`, `page` сброшен на 1, счётчики прочих фасетов пересчитаны без учёта `poles`.

**AC-CAT-2 — диапазон цены (нормализация)** 🟢
- Дано: URL `priceMin=500&priceMax=100`.
- Когда: парсинг параметров.
- Тогда: значения меняются местами (min=100, max=500).

**AC-CAT-3 — пустой результат (fail)** 🟢
- Дано: комбинация фильтров без совпадений.
- Когда: рендер.
- Тогда: список пуст, опции с count=0 — `disabled`, выбранные значения остаются видимыми и снимаемыми.

## Зависимости
`core-infra` (Prisma, i18n, кэш), `search` (альтернативный путь), `product` (карточки).

## Лакуны 🔴
- Синхронность SQL-выдачи и in-memory счётчиков (C-2).
- Единый источник конфигурации фильтров (C-3).
