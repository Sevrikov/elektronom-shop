# Требования — модуль `cart-checkout-orders`

> SDD (Writer, `completo`, hybrid) · Reversa. 🟢/🟡/🔴.

## Назначение
Корзина (гость/авторизованный), оформление заказа с атомарной транзакцией, история заказов пользователя.

## Функциональные требования (MoSCoW)
### Must
- **FR-ORD-1** 🟢 Корзина: гость → httpOnly-cookie (30 дней); авторизованный → `CartItem`. CRUD: add/update/remove/clear.
- **FR-ORD-2** 🟢 Слияние гостевой корзины в БД при входе (`mergeCartIfNeeded`), очистка cookie.
- **FR-ORD-3** 🟢 Количество `1..99`, не больше `stock`.
- **FR-ORD-4** 🟢 Оформление `createOrder`: идемпотентность по `idempotencyKey`, валидация наличия, атомарная транзакция.
- **FR-ORD-5** 🟢 Гонко-безопасное списание стока (условный `updateMany`, откат при недостатке).
- **FR-ORD-6** 🟢 Номер заказа `ORD-YYYY-NNNNN` через `OrderCounter` в транзакции.
- **FR-ORD-7** 🟢 Снапшоты покупателя/позиций; очистка корзины в транзакции.
- **FR-ORD-8** 🟢 История заказов (`getUserOrders`, пагинация 10) и заказ по номеру с проверкой владения.
### Should
- **FR-ORD-9** 🟢 Способы оплаты: `CARD_ONLINE|CASH_ON_DELIVERY|MONOBANK_PARTS|PRIVAT_PARTS`.
- **FR-ORD-10** 🟢 Cookie `last_created_order` (5 мин) для страницы успеха гостя.
### Won't (текущее)
- **FR-ORD-11** 🔴 Расчёт доставки (`shipping=0`) и промокодов (`discount=0`).
- **FR-ORD-12** 🔴 Инициация онлайн-оплаты / обработка webhook.

## НФТ
- **NFR-ORD-1 (Consistency)** 🟢 Все критичные операции — в `prisma.$transaction`.
- **NFR-ORD-2 (Concurrency)** 🟢 Оптимистичная блокировка стока предотвращает oversell.
- **NFR-ORD-3 (Idempotency)** 🟢 Повтор с тем же ключом не создаёт дубль.

## Критерии приёмки
**AC-ORD-1 (happy)** 🟢 Дано: корзина с доступными товарами; Когда: `createOrder`; Тогда: заказ `ORD-YYYY-NNNNN`, сток списан, корзина очищена.
**AC-ORD-2 (недостаток стока, fail)** 🟢 Дано: запрошено больше, чем `stock`; Когда: транзакция; Тогда: откат, ошибка «Недостатньо товару».
**AC-ORD-3 (двойной сабмит)** 🟢 Дано: тот же `idempotencyKey`; Когда: повтор; Тогда: возвращается прежний `orderNumber`, новый заказ не создаётся.
**AC-ORD-4 (доступ к заказу, fail)** 🟢 Дано: чужой `userId`; Когда: `getOrderByNumber`; Тогда: null.

## Зависимости
`catalog` (товары/сток), `auth-account` (сессия), `core-infra`.

## Лакуны 🔴
Оплата (BR-ORD-7), доставка/промо (BR-ORD-6), `addressId` не привязан (O-5), видимость гостевых заказов (O-6), дубль `getUserOrders` (O-7).
