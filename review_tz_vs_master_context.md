## 🔴 Критические (влияют на разработку)

### 1. `store/cart-store.ts` — конфликт назначения

В MASTER_CONTEXT §14 написано, что CartItem хранится в **БД** (модель `CartItem`), гостевая корзина — в cookie.  
В ТЗ часть 3 §14 написано:
> `store/cart-store.ts` — только UI: `isDrawerOpen, openDrawer, closeDrawer`

А в сводном ТЗ задача 1.17 говорит:
> `Zustand stores` — `cart-store.ts`, `ui-store.ts`

Получается два файла делают одно. Нет чёткого разделения — что конкретно в `cart-store.ts`, а что в `ui-store.ts`. Часть 3 это уточняет (cart = только drawer state), но сводное ТЗ может ввести в заблуждение агента.

**Исправление:** В задаче 1.17 сводного ТЗ явно написать:
- `cart-store.ts` — только `isDrawerOpen / openDrawer / closeDrawer`
- `ui-store.ts` — `isMobileMenuOpen`, `isSearchOpen`

---

### 2. Формулировка запрета `revalidate` — неточная

В коде из §20 MASTER_CONTEXT используется `import { revalidateTag } from 'next/cache'`.  
При этом критическое требование в сводном ТЗ гласит:
> ⛔ `export const revalidate` → замінити на `'use cache'` + `cacheLife()`

`revalidateTag` и `export const revalidate = N` — разные вещи. `revalidateTag` остаётся в Next.js 16 и не запрещён. Запрет касается только сегментной переменной `export const revalidate`.

**Исправление:** Уточнить формулировку:
> ⛔ `export const revalidate = N` → замінити на `'use cache'` + `cacheLife()`  
> ✅ `revalidateTag(...)` — дозволено і використовується в actions

---

### 3. `<img>` в примере `search-box.tsx` из MASTER_CONTEXT §20

В примере кода `search-box.tsx`:
```tsx
<img src={hit.image} alt={hit.name} className="h-12 w-12 rounded object-cover" />
```
Это прямо нарушает правило из того же документа:
> ⛔ `<img>` без `next/image` — ЗАПРЕЩЕНО

ТЗ это не исправляет и не комментирует.

**Исправление:** В MASTER_CONTEXT §20 заменить `<img>` на `<Image>` из `next/image` с `width`, `height`, `alt`.
