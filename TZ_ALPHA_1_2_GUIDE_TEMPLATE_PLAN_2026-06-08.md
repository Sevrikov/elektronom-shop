# Guide Template Plan

## Goal
Проектирование структуры и семантического шаблона пошагового руководства (гайда) для контент-хаба Electronom в рамках Alpha 1.2. Шаблон направлен на повышение видимости в поисковой выдаче (SEO), совместимость с ИИ-ответами (AEO), укрепление E-E-A-T сигналов магазина и конверсию информационного трафика в продажи.

## Current Blog Template
Текущий шаблон детальной страницы блога (`src/app/[locale]/(shop)/blog/[slug]/page.tsx`):
- Выводит обложку, хлебные крошки, дату публикации, время чтения и контент статьи из локального статического HTML.
- Поддерживает блок "Рекомендованное оборудование" (related products), который осуществляет prisma-запрос к БД на основе совпадения ключевых слов `productKeywords` статьи с именем или артикулом товара.

## Proposed Guide Structure
Для полноценного раскрытия интента пользователя структура гайда строится по следующим правилам:
1. **Заголовок (H1):** Формулируется строго под конкретный intent пользователя (например, *«Как правильно выбрать автоматический выключатель для дома»*).
2. **Direct Answer Block (AEO):** Идет первым контентным блоком до оглавления (Table of Contents), дословно и емко (40–80 слов) отвечает на интент, сформулированный в H1.
3. **Содержание (Table of Contents):** Для быстрого перехода по разделам.
4. **Вопросные подзаголовки (H2/H3):** Заголовки разделов формулируются как частые вопросы пользователей (например, *«Какой номинал автомата нужен на розетки?»*).
5. **Таблица выбора:** Сравнительная таблица параметров подбора (Параметр / Что означает / Как выбрать). Использует единый словарь характеристик и направлений из конфигурации сравнения (`compare-config`), гарантируя консистентность технических параметров товаров на всем сайте.
6. **Блок «Подойдет / Не подойдет»:** Четкое разделение применимости оборудования в зависимости от условий эксплуатации.
7. **Блок «Частые ошибки при выборе»:** Разбор неверных паттернов выбора покупателей.
8. **Рекомендации категорий и товаров:** Блоки перехода к коммерческим страницам каталога.
9. **FAQ-блок:** Часто задаваемые вопросы, размещаемые в конце статьи. Схемы `FAQPage` JSON-LD для этого блока выводятся строго под управлением отдельного фич-флага `alpha12_faq_howto_schema_enabled`.

## AEO Blocks
- **Direct Answer Block:** Визуально выделяется (рамка/фоновый цвет) и содержит чистый текст без внутренних ссылок для удобства парсинга поисковыми роботами и LLM.
- **Таблицы параметров:** Верстаются в стандартном HTML (`<table>`) для автоматического извлечения структурированных данных поисковыми сниппетами.

## SEO Metadata
- **Обязательное требование:** Генерация метаданных (Title, Description, Alternates) осуществляется динамически через `generateMetadata` на основе локализованных свойств статических объектов статей. Для каждой страницы генерируются `alternates.canonical` (абсолютный адрес через `getSiteUrl()`) и `languages: { uk: '...', ru: '...' }` (hreflang-ссылки для обеих локалей).
- Поле `description` должно лаконично описывать интент статьи и включать ключевые слова.

## Article Schema Compatibility
- JSON-LD разметка `Article`/`BlogPosting` генерируется сервером через компонент `<ArticleSchema />`.
- **Ограничение:** Разметка подключается только при включенном фич-флаге `alpha12_article_schema_enabled`.
- Разметка `FAQPage` / `HowTo` для соответствующих блоков выводится только при включенном флаге `alpha12_faq_howto_schema_enabled`.
- **E-E-A-T:** Схемы `Person` (для авторов и рецензентов) не добавляются до тех пор, пока данные об авторах не будут визуально отображаться на страницах и не будут согласованы с бизнесом.

## Internal Linking
- Текст статей должен содержать естественные ссылки на целевые коммерческие категории и карточки товаров с анкорами, соответствующими интенту.
- В конце статьи выводятся ссылки на смежные руководства из блога для увеличения глубины просмотра.

## Product/Category Integration
- **Автоматический подбор товаров:** На основе `productKeywords` статьи через prisma-запрос (поиск по совпадению с названием или SKU).
- **Связанные категории:** Вывод ссылок на разделы каталога на основе `categoryKeywords` статьи для перевода информационного трафика в коммерческий.

## E-E-A-T Rules
- Разметка автора (`Person`) и рецензента (`reviewedBy`) внедряется только на отдельном будущем этапе после A12-2.5, когда появится видимый блок автора и бизнес подтвердит реальные данные автора/рецензента.
- Никаких "фейковых" авторов или рецензентов в микроразметку не добавляется.
- Даты публикации (`datePublished`) и изменения (`dateModified`) должны быть четко видны пользователю и соответствовать микроразметке.

## RAG Readiness
- Контент гайдов на текущем этапе базируется на **Static Articles MVP** (хранение в `src/lib/articles.ts` и `articleContents`), что не требует миграций БД и изменений Prisma.
- Текст статей готов к автоматической нарезке на чанки для БД-модели `DocumentChunk` и привязке к `TechnicalDocument` через фоновые задачи индексации статического HTML-контента.
- **RAG-дисциплина контента:**
  - Каждый раздел статьи должен быть спроектирован как изолированный, самодостаточный семантический чанк. Использование относительных отсылок вроде "как было сказано выше" или "в предыдущем разделе" не допускается, чтобы не ломать логику при векторизации и выдаче чанков.
  - Все технические факты, номиналы, правила подбора оборудования должны быть тщательно выверены. Так как AI-ассистент цитирует этот контент пользователям, любая фактологическая ошибка в статье приравнивается к ложной информации от лица бренда.

## Feature Flags
- `alpha12_article_schema_enabled` — управление выводом JSON-LD (Article/BlogPosting).
- `alpha12_faq_howto_schema_enabled` — управление выводом JSON-LD для FAQPage/HowTo.
- `alpha12_content_guides_enabled` — перспективный (будущий) фич-флаг для управления отображением новых шаблонов руководств после их реализации.

## Implementation Phases
1. **Phase 1 (MVP):** Подготовка статических HTML-шаблонов статей с AEO/SEO блоками в `articleContents`.
2. **Phase 2 (E-E-A-T):** Визуальный вывод блока автора на детальной странице блога, согласование авторов с бизнесом.
3. **Phase 3 (Schema Expansion):** Подключение схем `Person` для авторов и рецензентов в JSON-LD.
4. **Phase 4 (DB Migration):** Перенос статей в БД (Prisma), разработка интерфейса админ-панели.

## Risks
- **Ручное обновление:** На этапе Static MVP любые изменения структуры разметки требуют ручной правки HTML-кода статей разработчиком.

## Definition of Done
- Документ сохранен в репозитории как `TZ_ALPHA_1_2_GUIDE_TEMPLATE_PLAN_2026-06-08.md`.
- Все обязательные разделы и ограничения полностью задокументированы.
- Изменения кода в данном шаге отсутствуют, база данных не затронута.
- В Git проиндексирован только файл плана.
