# ТЗ: переходы в категории магазина и фильтры выбора в стиле крупного маркетплейса

Дата: 2026-05-26  
Проект: Elektronom  
Цель: доработать страницы категорий каталога до удобного marketplace-уровня: дерево категорий, быстрые фильтры, фасетная навигация, SEO-safe URL, mobile drawer и корректная фильтрация товаров по атрибутам.

Важно: не копировать дизайн Rozetka пиксель-в-пиксель. Использовать проверенный UX-паттерн крупного интернет-магазина: слева дерево/фильтры, сверху сортировка и быстрые чипы, в центре товарная выдача, на мобильном — выезжающая панель фильтров.

---

## 1. Контекст текущего проекта

В проекте уже есть основа:

- страница категории: `src/app/[locale]/(shop)/catalog/[slug]/page.tsx`;
- фильтры: `src/components/catalog/catalog-filters.tsx`;
- активные фильтры: `src/components/catalog/active-filters.tsx`;
- сетка товаров: `src/components/catalog/product-grid.tsx`;
- price range: `src/components/catalog/price-range-filter.tsx`;
- query товаров: `src/queries/products.ts`;
- query категорий: `src/queries/categories.ts`;
- модель `Product.attributes Json` в Prisma;
- GIN-индекс для JSONB-атрибутов уже важен для производительности.

Текущая проблема: UI фильтров уже может показывать динамические атрибуты, но страница категории должна гарантированно передавать активные атрибуты в `getFilteredProducts()`, а запрос должен реально фильтровать по JSONB.

## 2. Целевой UX

### Desktop

Страница категории должна иметь структуру:

```text
Breadcrumbs
H1 категории + количество товаров
Подкатегории/быстрые группы
Active filter chips

┌──────────────────────┬──────────────────────────────────────────────┐
│ Sidebar              │ Toolbar: found count / sort / view / filters │
│ - Категории          │ Product grid/list                            │
│ - Цена               │ Pagination / show more                       │
│ - Наличие            │ SEO text / category description              │
│ - Бренд              │                                              │
│ - Атрибуты           │                                              │
└──────────────────────┴──────────────────────────────────────────────┘
```

Sidebar фиксируется при скролле (`sticky`), но не перекрывает header.

### Mobile

На мобильном:

- фильтры не занимают экран постоянно;
- над товарами показывается компактная панель:
  - кнопка `Фільтри`;
  - сортировка;
  - количество товаров;
  - active chips горизонтальным скроллом;
- по клику `Фільтри` открывается bottom sheet/drawer;
- фон затемняется;
- drawer закрывается по:
  - кнопке X;
  - клику на backdrop;
  - Escape;
  - свайпу вниз, если реализуется;
- внизу drawer sticky action bar:
  - `Показати N товарів`;
  - `Очистити`;
- drawer не перекрывает mobile bottom nav без отступа.

## 3. Категорийная навигация

### 3.1 Левый блок категорий

Добавить в sidebar категорийный блок выше фильтров:

```text
Категорії
  Всі товари категорії
  Підкатегорія 1 (123)
  Підкатегорія 2 (57)
  Підкатегорія 3 (12)
```

Требования:

- текущая категория подсвечена;
- дочерние категории показываются как быстрый переход;
- если категория имеет родителя, показывать siblings;
- если есть дочерние категории, показывать их;
- у каждой категории показывать count активных товаров;
- переход по категории должен сохранять релевантные фильтры только если они применимы к новой категории. Иначе сбрасывать несовместимые атрибуты.

### 3.2 Верхние плитки подкатегорий

Под H1 добавить горизонтальные/сеточные быстрые плитки подкатегорий:

```text
[Автоматичні вимикачі] [Розетки] [Кабель] [Щити] ...
```

Для desktop: сетка 4-6 колонок.  
Для mobile: горизонтальный скролл.

## 4. Фильтры

### 4.1 Базовые фильтры

Обязательные фильтры:

- наличие: `В наявності`;
- цена: `priceMin`, `priceMax`;
- бренд: `brand`;
- скидка/акция: `discount=1` или `promo=1`, если есть данные;
- новинки: `new=1`, если есть логика;
- рейтинг: только после полноценного review/rating aggregation;
- динамические атрибуты из `Product.attributes`.

### 4.2 Динамические атрибуты

Для технических товаров ключевые фильтры должны идти первыми:

Для электрики:

- номинальный ток;
- количество полюсов;
- характеристика отключения;
- тип монтажа;
- серия;
- напряжение;
- производитель;
- степень защиты IP.

Для масел/авто:

- вязкость;
- объём;
- тип;
- API;
- ACEA;
- совместимость.

Для аккумуляторов:

- напряжение;
- ёмкость;
- технология;
- тип клемм;
- ресурс/циклы;
- габариты.

Требование: порядок фильтров должен управляться конфигом категории, а не случайным порядком JSON keys.

## 5. URL и состояние фильтров

### 5.1 Query-параметры

Использовать человеко-понятные query-параметры:

```text
/uk/catalog/motornye-masla?brand=castrol,shell&viscosity=5W-30,5W-40&priceMin=500&priceMax=2500&inStock=1&sort=price-asc&page=2
```

Правила:

- multi-select значения через запятую;
- `page` сбрасывается при любом изменении фильтра;
- `sort` сохраняется при снятии фильтра;
- пустые значения удаляются из URL;
- порядок параметров стабилизировать для чистых ссылок;
- не использовать hash-state или localStorage как основной источник истины.

### 5.2 SEO

Индексировать:

- базовые категории;
- важные посадочные страницы, если они явно созданы как SEO landing.

Не индексировать бесконечные комбинации фильтров:

- добавить canonical на базовую категорию или на SEO landing;
- для произвольных query filter pages можно `noindex,follow`, если SEO-стратегия так решит;
- не генерировать sitemap для всех комбинаций фильтров.

## 6. Backend и Prisma

### 6.1 Исправить передачу attributes

В `src/app/[locale]/(shop)/catalog/[slug]/page.tsx` нужно передавать динамические атрибуты в `getFilteredProducts()`.

Сейчас передаются бренд/цена/наличие/сортировка/page, но не все `activeFilters` по атрибутам.

Нужно сформировать:

```ts
const attributeFilters = buildAttributeFilters(activeFilters, filters)
```

И передать:

```ts
attributes: attributeFilters
```

### 6.2 Реализовать JSONB-фильтрацию в `getFilteredProducts`

Файл:

`src/queries/products.ts`

Требование:

- для каждого атрибута поддержать multi-select;
- внутри одного атрибута логика OR;
- между разными атрибутами логика AND.

Пример:

```text
viscosity = 5W-30 OR 5W-40
AND
type = synthetic
AND
brand = castrol OR shell
```

В Prisma для JSONB может понадобиться `path`/`equals`/`array_contains` или raw SQL, если Prisma-выражения недостаточно гибкие. Если используется raw SQL:

- только параметризованный запрос;
- не собирать SQL строками из пользовательского ввода;
- сохранить `take`/`skip`;
- выбрать только нужные поля (`select`);
- не нарушать AGENTS.md.

### 6.3 Facet counts

Counts должны показывать, сколько товаров останется при выборе значения.

MVP:

- counts считаются по всей категории без учёта текущих фильтров.

Production:

- counts пересчитываются с учётом активных фильтров, кроме текущей группы.

Пример:

```text
Бренд:
[x] Castrol (5)
[ ] Shell (3)
[ ] Mobil (2)

Вязкість:
[x] 5W-30 (4)
[ ] 5W-40 (1)
```

### 7.4 Важно: не переделывать карточки с нуля

На главной странице Elektronom уже есть товарные карточки/блоки товаров в нижней части страницы. Их нужно считать текущей базой визуального языка, а не выбрасывать.

Задача разработчика:

- переиспользовать существующий `ProductCard` как основу;
- не делать новый несовместимый дизайн карточки только для категории;
- доработать карточку под категорийную выдачу, если не хватает данных;
- сохранить единый стиль с главной и каталогом.

Что именно нужно адаптировать для категории:

- карточка в grid должна быть компактнее, чем промо-блоки на главной;
- в карточке категории желательно показывать 3-5 ключевых характеристик из `Product.attributes`;
- бейджи: `В наявності`, `Акція`, `Топ продажів`, `Знижка`;
- цена, старая цена, скидка;
- кнопка корзины;
- wishlist/compare позже, если уже есть инфраструктура;
- высота карточек в одной строке должна быть стабильной;
- длинные названия ограничивать `line-clamp`, не ломая сетку.

Отдельно:

- для category grid использовать существующую карточку в режиме `catalog`;
- для homepage можно сохранить более “витринный” режим;
- если нужен другой layout, добавить prop/mode, например `variant="catalog" | "home" | "compact"`, а не создавать второй независимый компонент.

### 7.2 `catalog-filter-url.ts`

## 8. UI/Design требования

Следовать стилю текущего Elektronom:

- фон страницы `bg-surface-alt`;
- карточки/панели `bg-surface-white`;
- границы `border-border`;
- акцент `bg-accent`;
- текст `text-text-primary`, `text-text-muted`;
- радиус не больше `rounded-lg`;
- без inline `style={{}}`, использовать Tailwind v4 tokens;
- использовать lucide icons.

### 8.1 Sidebar

Sidebar:

- белая панель;
- секции с раскрытием;
- count справа;
- поиск внутри длинных списков;
- `Показати ще` после 8 значений;
- выбранные пункты подчёркнуты чекбоксом/акцентом.

### 8.2 Active chips

Активные фильтры:

```text
[Castrol ×] [5W-30 ×] [500–2500 ₴ ×] [В наявності ×] [Очистити все]
```

Требования:

- удалить один фильтр;
- удалить одно значение multi-select;
- очистить все, сохранив `sort` при необходимости;
- на mobile — горизонтальный scroll.

### 8.3 Toolbar

Toolbar над товарами:

- найдено N товаров;
- сортировка;
- переключатель вид: grid/list;
- mobile-кнопка фильтров;
- при pending URL transition показать subtle loading state.

## 10. Performance

Требования:

- все Prisma collection queries с `take`/`skip`;
- не использовать `include`, только `select`;
- не тянуть все товары без лимита;
- counts кэшировать через `'use cache'`, `cacheLife`, `cacheTag`, где это применимо;
- фильтрованная выдача остаётся динамической;
- не делать N+1 запросы по каждому фильтру на каждый render;
- для JSONB attributes сохранить/проверить GIN-index `products_attributes_gin_idx`;
- для больших категорий предусмотреть ограничение количества facet values, например top 50 + search.

## 11. Acceptance Criteria

Задача считается готовой, если:

1. На странице категории есть desktop sidebar с категориями и фильтрами.
2. На mobile фильтры открываются в drawer/bottom sheet.
3. Бренд, цена, наличие и динамические атрибуты реально фильтруют товары.
4. Multi-select работает через URL.
5. Выбранные фильтры отображаются active chips.
6. Удаление одного chip меняет выдачу без полной перезагрузки страницы.
7. `page` сбрасывается при изменении фильтра.
8. `sort` сохраняется при снятии фильтров.
9. Counts отображаются рядом со значениями.
10. Подкатегории видны и работают как переходы.
11. Нельзя получить ошибку при неизвестном/пустом query параметре.
12. Ссылки локализованы: `/uk/...`, `/ru/...`.
13. Нет inline styles в новых/изменённых компонентах.
14. `npm run lint` проходит.
15. `npx tsc --noEmit` проходит.
16. `npm run build` проходит.
17. Проверены desktop 1440px, tablet 768px, mobile 390px.

## 12. Рекомендуемые тестовые сценарии

### Desktop

1. Открыть `/uk/catalog/motornye-masla`.
2. Выбрать бренд `Castrol`.
3. Выбрать `5W-30`.
4. Установить цену.
5. Включить `В наявності`.
6. Проверить, что URL содержит параметры.
7. Обновить страницу — состояние фильтров сохранено.
8. Удалить chip `5W-30` — товарная выдача меняется.
9. Очистить все — остаётся базовая категория.

### Mobile

1. Открыть страницу на 390px.
2. Нажать `Фільтри`.
3. Выбрать 2 фильтра.
4. Нажать `Показати N товарів`.
5. Drawer закрывается, выдача обновлена.
6. Mobile bottom nav не перекрыт.

### Edge cases

- неизвестный фильтр в URL;
- пустой фильтр `brand=`;
- несуществующее значение `viscosity=BAD`;
- `priceMin > priceMax`;
- `page` больше total pages;
- категория без товаров;
- категория без дочерних категорий;
- категория с 50+ брендами.
