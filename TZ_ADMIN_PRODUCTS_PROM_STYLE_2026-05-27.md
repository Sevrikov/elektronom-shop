# ТЗ: админка товаров Elektronom по логике Prom.ua

Дата: 2026-05-27  
Проект: `C:\Users\sevri\Сайт\elektronom`  
Раздел: `/[locale]/admin`, вкладка `Товары`  
Ориентир UX: кабинет компании Prom.ua, раздел `Товари та послуги → Товари / Перелік позицій`.

## 1. Цель

Сделать в админке Elektronom первый рабочий центр управления товарами, похожий по логике на Prom.ua: не просто CRUD-форма, а удобный операторский экран для ежедневной работы с большим каталогом.

Администратор должен быстро видеть:

- сколько товаров добавлено;
- сколько опубликовано;
- сколько активно на сайте;
- сколько неактивно;
- сколько без фото;
- сколько без цены;
- сколько нет в наличии;
- какие товары требуют внимания;
- какие товары можно быстро отредактировать, скрыть, удалить, продублировать или выгрузить.

## 2. Что увидено в Prom.ua и что нужно перенести по смыслу

Prom.ua в разделе товаров строит экран вокруг таких блоков:

### 2.1. Левое меню

В Prom есть вертикальная навигация:

- Замовлення;
- Товари та послуги;
- Товари;
- Популярні товари;
- Імпорт;
- Групи та добірки;
- Категорії;
- Видалені товари;
- Відновлення товарів;
- Характеристики;
- Покупці;
- Відгуки та запитання;
- Аналітика;
- Інструменти веб-майстра та SEO;
- Управління сайтом;
- Налаштування.

Для Elektronom на Sprint 1 достаточно сделать в админке стабильную структуру:

- Обзор;
- Товары;
- Категории;
- Бренды;
- Характеристики/фильтры;
- Заказы;
- Отзывы;
- Баннеры/контент;
- SEO;
- Настройки.

### 2.2. Верхняя зона раздела товаров

В Prom вверху раздела есть:

- заголовок `Перелік позицій`;
- кнопка `Експорт`;
- кнопка `Додати товар`;
- счетчик добавленных товаров;
- счетчик разновидностей/вариантов;
- счетчик опубликованных;
- счетчик товаров в каталоге;
- счетчик товаров не в каталоге;
- быстрые проблемные фильтры `Немає фото`, `Немає ціни`;
- блок `Збережені фільтри`.

Для Elektronom нужно сделать похожую KPI-панель:

- `Всего товаров`;
- `Активные на сайте`;
- `Неактивные`;
- `В наличии`;
- `Нет в наличии`;
- `Без фото`;
- `Без цены`;
- `Без категории`;
- `С ошибками SEO`;
- `Featured / топ`.

Важно: эти показатели должны быть кликабельными фильтрами. Например, клик по `Без фото` сразу показывает только товары без изображений.

### 2.3. Таблица товаров

В Prom таблица показывает:

- чекбокс выбора;
- фото/миниатюра;
- название товара;
- категория/группа;
- бренд;
- дата добавления/обновления;
- код/SKU;
- отображение/наличие;
- цена;
- тип цены;
- заказы;
- действия.

Для Elektronom таблица должна иметь колонки:

| Колонка | Содержание |
|---|---|
| Выбор | чекбокс для массовых действий |
| Фото | главное изображение товара |
| Название | UA/RU название, slug, ссылка на storefront |
| Категория | текущая категория, возможность быстрого перехода |
| Бренд | бренд |
| SKU | артикул |
| Статус | активен/скрыт, опубликован/не опубликован |
| Наличие | stock, статус “в наличии / нет” |
| Цена | price, comparePrice, costPrice только для админа |
| SEO | индикатор заполненности title/description/slug |
| Заказы | количество заказов по товару, если доступно |
| Обновлено | дата изменения |
| Действия | меню действий |

## 3. Требования к вкладке “Товары”

### 3.1. Страница списка товаров

Файл-ориентир текущей реализации:

- `src/app/[locale]/admin/admin-panel-client.tsx`
- `src/actions/admin.ts`

Нужно переработать вкладку `products`, не ломая остальные вкладки.

Экран должен включать:

1. Заголовок `Товары`.
2. Основные кнопки:
   - `Добавить товар`;
   - `Импорт`;
   - `Экспорт`;
   - `Обновить`;
   - в будущем `AI-контент`.
3. KPI-панель качества каталога.
4. Панель сохранённых фильтров.
5. Фильтры и поиск.
6. Таблицу товаров.
7. Массовые действия.
8. Пагинацию и выбор количества строк.

### 3.2. KPI-панель

Сделать компактные карточки/чипы над таблицей:

- `Всего`: count всех товаров;
- `Активные`: `isActive = true`;
- `Скрытые`: `isActive = false`;
- `В наличии`: `stock > 0`;
- `Нет в наличии`: `stock = 0`;
- `Без фото`: нет записей `ProductImage`;
- `Без цены`: `price <= 0` или null, если схема допускает;
- `Без бренда`: `brandId = null`;
- `Featured`: `isFeatured = true`.

Каждый KPI работает как быстрый фильтр.

Для `getProductsAdmin()` нужно добавить режим получения `facets/stats`, например:

```ts
getProductsAdmin({
  page,
  limit,
  search,
  categoryId,
  brandId,
  status,
  stock,
  quality,
  sort,
})
```

И отдельный запрос:

```ts
getProductAdminStats()
```

Все Prisma collection-запросы обязаны иметь `take/skip` и `select`.

### 3.3. Фильтры

Минимальный набор фильтров Sprint 1:

- поиск по названию / SKU / slug;
- категория;
- бренд;

  - все;
  - активные;
  - скрытые;
- наличие:
  - все;
  - в наличии;
  - нет в наличии;
- качество карточки:
  - без фото;
  - без цены;
  - без бренда;
  - без описания UA;
  - без описания RU;
- featured:
  - все;
  - featured;
  - обычные.

Фильтры должны сохраняться в URL query, чтобы можно было отправить ссылку разработчику/контент-менеджеру.

Пример:

```text

```

### 3.5. Таблица

Таблица должна быть плотной, как рабочий инструмент, а не карточный маркетинговый экран.

Поведение:

- sticky header таблицы;
- чекбоксы выбора строк;
- сортировка по:
  - дате создания;
  - дате обновления;
  - цене;
  - остатку;
  - названию;

- изображение 48-64 px;

- статус активный/скрыт как badge;

### 3.6. Меню действий товара

В каждой строке добавить меню `Действия`:

## 5. Backend / Server Actions

Расширить `src/actions/admin.ts`.

### 5.1. Доработать `getProductsAdmin`

Сейчас есть:

```ts
getProductsAdmin(page, limit, search, categoryId, brandId)
```

Нужно перейти к объектному API:

```ts
getProductsAdmin({
  page,
  limit,
  search,
  categoryId,
  brandId,
  active,
  stockState,
  quality,
  featured,
  sort,
})
```

Причина: иначе параметры быстро станут нечитаемыми.

### 5.2. Добавить `getProductAdminStats`

Возвращает:

```ts
{
  total: number
  active: number
  inactive: number
  inStock: number
  outOfStock: number
  withoutImages: number
  withoutPrice: number
  withoutBrand: number
  featured: number
}
```

### 5.3. Добавить bulk actions

Минимум:

```ts
bulkToggleProductsActiveAdmin(ids: string[], isActive: boolean)
bulkSyncProductsAlgoliaAdmin(ids: string[])
bulkUpdateProductsCategoryAdmin(ids: string[], categoryId: string)
bulkUpdateProductsBrandAdmin(ids: string[], brandId: string | null)
```

Требования:

- `ids` валидировать через `z.array(z.string().min(1)).min(1).max(100)`;
- после изменения товара синхронизировать Algolia;
- использовать `revalidateTag('products', 'max')`;
- не использовать `z.string().cuid()`.

## 7. Дизайн

Админка должна быть плотной и рабочей:

- без hero-блоков;
- без декоративных карточек внутри карточек;
- таблица и фильтры должны быть компактными;
- высота строки таблицы ориентировочно 72-88 px;
- радиус элементов до 8 px;
- цветовые токены из Tailwind v4 theme;
- без inline styles;
- icon buttons с lucide icons;
- все опасные действия красным/destructive;
- статусы и проблемы через badges.

## 8. Интеграция с существующими требованиями проекта

Обязательно соблюдать:

- Next.js 16: не добавлять route config `revalidate/dynamic`;
- Prisma: collection-запросы только с `take/skip`;
- Prisma: только `select`, не `include`;
- Prisma: импорт только из `@/lib/prisma`;
- Tailwind v4: без `tailwind.config.ts`, без inline styles;
- Zod: не использовать `.cuid()`;
- Algolia: все create/update/delete/toggleActive должны синхронизировать индекс.

## 9. Acceptance Criteria

Задача считается готовой, если:

1. В `/uk/admin` есть вкладка `Товары` с Prom-подобной структурой.
2. Видна KPI-панель качества каталога.
3. KPI-карточки кликабельны и применяют фильтры.
4. Есть фильтры по поиску, категории, бренду, активности, наличию, качеству карточки.
5. Есть saved/system filters.
6. Таблица показывает фото, название, категорию, бренд, SKU, статус, наличие, цену, заказы/0, дату, действия.
7. Есть меню действий товара.
8. Есть массовый выбор строк и action bar.
9. Редактирование товара не ломает Cloudinary image uploader.
10. После изменения товара обновляется Algolia.
11. `npm run lint` — 0 errors/warnings.
12. `npx tsc --noEmit` — 0 errors.
13. `npm run build` — success.

Эти вещи важны, но сначала нужен быстрый, надёжный, Prom-like товарный backoffice.
