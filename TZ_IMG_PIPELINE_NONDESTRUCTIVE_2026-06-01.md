# ТЗ — Неразрушающий пайплайн изображений (оригинал ↔ вырезанный фон)

> Дата: 2026-06-01. Уточняет R-2b (`TZ_REMAINING_FIXES`). Развивает уже сделанное (поле `ProductImage.processedUrl`, eager-трансформация, backfill-скрипт).
> Правила: `MASTER_CONTEXT`+addendum, §0 anti-regression, без `any`, `select`+`take`.

## 🎯 Принцип (главное)
1. **Оригинал — священен.** Исходное изображение в БД/хранилище **НИКОГДА** не перезаписывается и не удаляется. Вырезанный фон **НЕ сохраняется поверх оригинала**.
2. **Вырезанная версия хранится ОТДЕЛЬНО** (`processedUrl`) и генерируется **один раз** (при загрузке/импорте), не на рендере.
3. **На сайт всегда отдаём ОБРАБОТАННУЮ версию** (вырезанную), с откатом на оригинал, если обработки ещё нет.

## 📦 Модель данных (`ProductImage`)
| Поле | Назначение | Правило |
|------|------------|---------|
| `url` | **ОРИГИНАЛ** (как загружен/импортирован) | ⛔ **неизменяемый** — никогда не перезаписывать вырезанным |
| `processedUrl` | Вырезанный фон (прозрачный PNG) | заполняется один раз; пусто = ещё не обработано |
| `provider` | LOCAL/CLOUDINARY/EXTERNAL | менять только если оригинал реально перезалит, **не теряя ссылку на оригинал** |

> Если есть риск, что миграция меняет `url` (перезалив в Cloudinary) — **сначала сохранить оригинал** (в `url` остаётся оригинал; перезалитый прозрачный → только в `processedUrl`). Опц. поле `originalUrl` как страховка, если `url` всё же меняется.

## ⛔ Абсолютные запреты
- ⛔ НЕ писать вырезанный результат в `ProductImage.url`.
- ⛔ НЕ удалять/не затирать исходный файл (Cloudinary public_id оригинала, локальный файл) при обработке/backfill.
- ⛔ НЕ применять вырезание фона **на рендере** (ни canvas, ни per-request трансформация) — только на ingestion.

## 🔧 Задачи

### IMG-1 Загрузка (upload) — оригинал + processedUrl
- `lib/storage.ts`/`actions/admin.ts`: при загрузке сохранять **оригинал** в `url`; eager-трансформация bg-removal → URL прозрачного в **`processedUrl`** (как уже сделано). Оригинал не трогать.
- **Приёмка:** после загрузки `url` = оригинал, `processedUrl` = вырезанный; оба доступны (200).

### IMG-2 Рендер — всегда обработанная, откат на оригинал
- Везде, где показываются товарные изображения (`product-card`, `product-gallery`, `same-series`, `cart-item`, листинг): источник = **`processedUrl ?? url`**.
- `lib/images.ts:getTransformedImageUrl` — отдавать `processedUrl` если есть; **без** трансформации на лету (как уже сделано). Обычный `next/image`.
- **Приёмка:** на сайте отображается вырезанная версия; если `processedUrl` пуст — оригинал (без блокировки рендера).

### IMG-3 Backfill — безопасный и идемпотентный
- `scripts/backfill-bg-removal.ts`: для изображений с `processedUrl = null` (приоритет — активные товары) → получить вырезанный URL → записать **только** `processedUrl`.
- **Гарантии:**
  - НЕ менять `url` (оригинал остаётся). Если требуется перезалив — оригинал сохранить (см. `originalUrl`).
  - **Идемпотентность:** уже обработанные (`processedUrl != null`) — пропускать.
  - При ошибке/пустом результате bg-removal — оставить `processedUrl = null`, оригинал не трогать (graceful, на сайте покажется оригинал).
  - Батчами (`--limit`), с логом «обработано/пропущено/ошибки».
- **Приёмка:** прогон по активным товарам; оригиналы целы; повторный прогон ничего не портит; прислать счётчики покрытия.

### IMG-4 Проверка Cloudinary bg-removal
- Убедиться, что add-on **AI Background Removal** включён, eager-трансформация реально даёт **прозрачный PNG** (а не оригинал/ошибку). Сверить 2–3 `processedUrl` глазами.
- **Приёмка:** `processedUrl` — действительно вырезанные изображения.
