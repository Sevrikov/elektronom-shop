# ТЗ — Иерархический пайплайн вырезания фона (категория → подкатегория → товар)

> Дата: 2026-06-01. Развивает: `TZ_IMG_PIPELINE_NONDESTRUCTIVE` (неразрушающее хранение) + R-2b (`TZ_REMAINING_FIXES`).
> Правила: `MASTER_CONTEXT`+addendum, §0 anti-regression, без `any`, `select`+`take`.

## 🎯 Принцип
1. **Неразрушающе** (унаследовано): оригинал `ProductImage.url`/`originalUrl` неприкосновенен; результат — в `processedUrl`; на сайт отдаём `processedUrl ?? url`; на рендере — без обработки.
2. **Экономия на дорогом ИИ:** основную массу режет **дешёвый алгоритм** с откалиброванными параметрами; **тяжёлый AI (Cloudinary)** — только на проблемных единицах.
3. **Калибровка параметров сверху вниз:** ИИ настраивает обработку **на уровне категории → затем подкатегории**, и **только проблемные изображения** обрабатываются индивидуально (per-товар). Внутри категории фото однотипны (поставщик/студия) → один профиль на категорию вместо 43k индивидуальных настроек.

## 🧱 Модель параметров (каскад «профилей обработки»)
Параметры алгоритма обрезки (`threshold, distBlock, minHoleSize, floorShadowY, outlineThreshMin, tBot, skipProcessing` — из существующего `image-arbitration.ts`) разрешаются **каскадом**:

```
эффективные параметры =
  per-image override          (исключения, точечно)
  ?? subcategory profile       (уточнение)
  ?? category profile          (базовый уровень калибровки)
  ?? default
```

- **Хранение профилей:** таблица `CategoryImageProfile { categoryId (unique), params Json, calibratedAt, sampleStats Json }` (или конфиг `src/config/image-profiles.ts`, генерируемый калибровкой). Per-image — существующий `image-arbitration.ts`.
- Подкатегория = та же таблица (профиль на её `categoryId`); наследование от родителя, если своего нет.

## 🔄 Пайплайн (offline / ingestion, не на рендере)
> Калибровка ИИ работает в среде с vision-MCP (orbis-vision) + Cloudinary + Neon. Прод просто отдаёт `processedUrl`.

### Этап A — Калибровка по КАТЕГОРИИ (ИИ via MCP)
Для каждой активной категории:
1. Взять **репрезентативную выборку** (N≈8–12 изображений).
2. **ИИ-анализ (orbis-vision/Florence2 via MCP):** тип фона (белый студийный / цветной / сложный), тени, контраст продукт/фон, наличие текста/мелких деталей.
3. **Подобрать параметры** алгоритма под категорию; прогнать выборку; оценить QA-метриками (см. ниже); итеративно подстроить (несколько итераций).
4. Сохранить `CategoryImageProfile` (+статистика: % выборки, прошедший порог).
**Приёмка:** у каждой категории есть профиль; на выборке качество ≥ порога.

### Этап B — Уточнение по ПОДКАТЕГОРИИ
Для каждой подкатегории:
1. Проверить на её выборке параметры родителя.
2. Если качество ниже порога → ИИ подстраивает **override** для подкатегории; иначе наследовать категорию.
**Приёмка:** подкатегории с отличающимися фото имеют свой профиль; остальные наследуют.

### Этап C — Массовая обработка по профилям (без ИИ на каждое)
1. Для всех изображений активных товаров: алгоритмическая обрезка с **эффективными параметрами** (каскад) — дёшево, без вызова ИИ/Cloudinary на каждое.
2. Результат (прозрачный PNG) → залить → записать `processedUrl` (оригинал в `url`/`originalUrl` не трогать).
3. Прогнать QA-метрику на результат; не прошедшие → пометить «проблемное» (Этап D).
**Приёмка:** масса изображений обработана профилями кат/подкат; идемпотентно (`processedUrl != null` — пропуск).

### Этап D — Исключения (per-товар, только проблемные)
Для изображений, не прошедших QA с профилем кат/подкат:
1. **ИИ-подстройка индивидуально** (per-image override в `image-arbitration`) → повтор алгоритма; ЛИБО
2. **Эскалация на Cloudinary AI bg-removal** (`e_background_removal`) — последний резерв (платно), только для этих единиц.
3. Записать `processedUrl` + пометить тир (для аналитики/стоимости).
**Приёмка:** проблемные доведены до качества или явно помечены (`processedUrl=null`, на сайте — оригинал, graceful).

## ✅ QA-гейт — что значит «нормальный результат»
Метрики **программные** (без ИИ на каждое — для скейла; ИИ — на калибровке и спорных):
- **Остаточный ореол:** доля непрозрачных светлых пикселей по краю (белая кайма) ≤ порог.
- **Дыры в продукте:** нет крупных прозрачных областей внутри тела продукта.
- **Над-вырезание:** доля удалённого не превышает ожидаемую (продукт не «съеден»).
- **Целостность краёв/мелких деталей** (текст, тонкие элементы) сохранена.
Ниже порога → следующий уровень/тир.

## 🧮 Тиеры обработки (внутри этапов C/D)
| Тир | Что | Когда |
|-----|-----|-------|
| 1 | Алгоритм (свой) с параметрами профиля | по умолчанию, масса |
| 2 | ИИ-проверка + подстройка параметров (кат/подкат, via MCP) | калибровка / спорные |
| 3 | Cloudinary AI bg-removal (платно) | только проблемные единицы |

> Цель: максимум через Тир 1 (профили), минимум через Тир 3.
