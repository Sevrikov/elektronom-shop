# ТЗ и методология усиления SEO / AI / GEO для Project Alpha V1.1

Дата: 2026-06-07
Проект: Elektronom, ветка развития Project Alpha V1.1
Цель: усилить органический трафик, видимость в Google Search, Shopping, AI Overviews / AI Mode и LLM-ответах без псевдо-AI-трюков, через технически корректную индексацию, полезный экспертный контент, структурированные данные, Merchant-инфраструктуру и измеримую систему контроля.

## 1. Главный принцип

Для Google нет отдельной "AI SEO" магии. Страницы должны быть индексируемыми, полезными, надежными, доступными для сниппетов, структурно понятными и богатыми фактическими данными. AI Overviews, AI Mode и LLM-ответы чаще берут страницы, которые уже хорошо отвечают на конкретные вопросы, имеют понятную HTML-структуру, видимый контент, подтверждающие данные и нормальную репутацию источника.

Для Elektronom это означает: не делать отдельный слой "для AI", а усилить продуктовые, категорийные и экспертные страницы так, чтобы они одновременно работали для:

- обычной выдачи Google;
- Google Shopping / Merchant Center;
- AI Overviews и AI Mode;
- голосовых и диалоговых ответов;
- пользователей, которые выбирают электротовары по характеристикам, совместимости и сценариям применения.

## 2. Исходная база сайта

### 2.1. Уже реализовано и считается сильной стороной

- Next.js 16, серверные страницы, SSR/metadata, современная архитектура.
- `src/app/robots.ts`: production-режим открыт для индексации, закрыты технические зоны `/api/`, `/admin/`, `/checkout/`, `/account/`, `/search`.
- `src/app/sitemap.ts`: генерирует базовые страницы, товары, категории, бренды, статьи и quick-link страницы, есть `alternates.languages`.
- `src/components/product/product-schema.tsx`: Product JSON-LD уже содержит offer, price, availability, shipping, return policy, brand, rating/review при наличии данных.
- `src/components/layout/breadcrumbs.tsx`: BreadcrumbList JSON-LD.
- `src/app/feed/[locale]/route.ts` и `src/lib/merchant/feed-builder.ts`: Merchant feed уже есть, строится пакетно, использует `select`, `take`, `skip`, Google taxonomy, availability, identifiers и цены.
- `src/app/[locale]/(shop)/catalog/[slug]/page.tsx`: есть логика canonical/noindex для фильтров, quick-link whitelist, AnswerBlock, category articles.
- `src/lib/direct-answers.ts`: уже есть основа для direct-answer блоков.
- `public/llms.txt`: присутствует как вспомогательный, но не ключевой SEO-фактор.

### 2.2. Главные зоны усиления

- Недостаточно прямых экспертных ответов по большинству категорий и фильтр-landing страниц.
- Product page нужно усилить не только schema, но и видимым контентом: FAQ, совместимость, монтаж, ошибки выбора, таблицы, реальные фото/видео, документы.
- Blog/guide слой пока ограничен, нужен системный content hub под информационные и коммерчески-информационные запросы.
- Нет отдельного Article JSON-LD / ItemList / FAQPage слоя там, где видимый контент это позволяет.
- Нужно валидировать NAP, Organization, контакты, авторов и экспертность, чтобы не было placeholder-данных.
- Sitemap сейчас допустим при текущем количестве активных товаров, но при росте активного каталога и двух локалях потребуется разделение.
- Не настроена регулярная методология контроля AI Overviews / AI Mode через новые отчеты Search Console, где они доступны.
- `llms.txt` нельзя считать стратегическим рычагом. Его поддерживаем, но не инвестируем в него как в канал ранжирования.

## 3. Источники и правила, на которые опирается ТЗ

- Google Search Central: AI features and your website. Вывод: нет специальных AI-разметок или AI-файлов; нужны индексируемость, snippet eligibility, полезный контент, структурированные данные, актуальные Merchant / Business данные.
- Google Search Central: Product structured data. Вывод: для e-commerce критичны Product / Offer / availability / shipping / return policy / reviews / identifiers.
- Google Search Central: Creating helpful, reliable, people-first content. Вывод: нужны оригинальность, полнота, экспертиза, доказательства, отсутствие контента "только для поисковиков".
- Google Search Central: robots meta tag. Вывод: `nosnippet` и `max-snippet:0` ограничивают использование контента в AI Overviews / AI Mode.
- Google Search Central: large sitemaps. Вывод: при росте URL нужно разделять sitemap и использовать sitemap index.
- Google Search Console, 2026-06-03: появились отдельные отчеты Gen AI для AI Overviews, AI Mode и Discover у части сайтов.
- Ahrefs / Semrush исследования AI Overviews. Вывод: AIO чаще срабатывают на информационных, вопросных, long-tail и сравнительных запросах; shopping-запросы затрагиваются слабее из-за специальных shopping SERP features.

## 4. Методология внедрения

### 4.1. Классификация страниц

Каждая страница должна попасть в один из типов:

- Product: товарная карточка, цель - транзакция, доверие, наличие, цена, совместимость.
- Category: листинг категории, цель - выбор группы товаров, фильтрация, быстрый переход.
- Quick-link landing: индексируемая страница под стабильную комбинацию фильтров, цель - long-tail коммерческий спрос.
- Guide / Article: экспертный материал, цель - AI citation, информационный трафик, внутренние переходы в каталог.
- Brand: страница бренда, цель - брендовые запросы, ассортимент, доверие.
- Info / Trust: контакты, доставка, возврат, гарантия, оплата, цель - доверие и entity-сигналы.

### 4.2. Матрица усиления

Для каждой страницы фиксируются:

- основной intent: купить, выбрать, сравнить, узнать, проверить совместимость;
- главный ответ в первых 300-500 символах;
- 3-7 supporting facts: характеристики, диапазоны, стандарты, ограничения;
- видимые доказательства: фото, видео, документы, отзывы, сертификаты, примеры применения;
- schema, которая соответствует видимому контенту;
- внутренние ссылки на товары, категории, бренды и статьи;
- индексируемость: index/canonical/noindex;
- KPI: показы, клики, CTR, позиции, AI visibility, конверсия.

### 4.3. Правила реализации в коде

- Соблюдать правила Next.js 16 из `AGENTS.md`.
- Не добавлять `export const revalidate`, `export const dynamic`, `unstable_cache`, React `cache()`, `middleware.ts`.
- Для серверного кэша использовать `'use cache'`, `cacheLife()`, `cacheTag()` внутри серверных функций.
- Pages оставлять Server Components. Интерактив выносить в маленькие leaf client components.
- В Prisma всегда использовать `select`; для коллекций всегда `take` / `skip`.
- Не добавлять inline styles. Использовать Tailwind v4 через классы и `src/app/globals.css`.
- Не добавлять schema для контента, которого нет на странице видимо для пользователя.
- Не использовать hidden text, doorway pages, массовую генерацию пустых страниц, fake reviews, fake FAQ.

## 5. Work Package 1: Crawl, Indexing, Snippet Readiness

### Цель

Убедиться, что Google и AI-функции могут видеть, индексировать и цитировать коммерчески важные страницы.

### Текущее состояние

- `src/app/robots.ts` настроен корректно для production.
- `src/app/sitemap.ts` уже включает товары, категории, бренды, статьи и quick links.
- Search/filter страницы закрываются от индексации через canonical/noindex, кроме whitelisted quick links.

### Задачи

1. Проверить production `robots.txt` после деплоя:
   - `Disallow` не должен блокировать товары, категории, бренды, статьи, quick links.
   - `Sitemap` должен вести на актуальный домен.
2. Проверить, что на индексируемых страницах нет:
   - `nosnippet`;
   - `max-snippet:0`;
   - случайных `noindex`;
   - canonical на другой URL без причины.
3. Ввести лимитный контроль sitemap:
   - если сумма URL с учетом локалей приближается к 45 000, подготовить split sitemap;
   - если превышает 50 000 URL или 50 MB, внедрить sitemap index.
4. Для quick-link страниц хранить whitelist в одном источнике правды:
   - включать только стабильные, коммерчески осмысленные фильтры;
   - не индексировать произвольные комбинации параметров.
5. Сделать технический crawl после каждого крупного релиза:
   - 200/3xx/4xx;
   - canonical;
   - title/description;
   - hreflang;
   - indexability;
   - structured data.

### Критерии приемки

- В GSC sitemap принят без ошибок.
- 95%+ индексируемых товарных и категорийных URL отдают 200.
- Нет product/category URL с `nosnippet` или `max-snippet:0`.
- Нет произвольных фильтров в sitemap.
- Для quick-link страниц canonical указывает на саму quick-link страницу.

## 6. Work Package 2: Product Page SEO / AI Усиление

### Цель

Сделать карточку товара не просто страницей цены, а источником выбора: что это, для чего подходит, как проверить совместимость, какие ограничения, как купить.

### Текущее состояние

- Product JSON-LD уже сильный.
- На странице есть галерея, характеристики, описание, отзывы, same series, related products, product articles.
- Требуется больше видимого экспертного контента и расширение данных.

### Задачи

1. Добавить к товарной странице блок "Короткий ответ":
   - 2-4 предложения;
   - что это за товар;
   - где применяется;
   - ключевая характеристика;
   - важное ограничение.
2. Добавить блок "Подойдет / не подойдет":
   - подходит для сценариев;
   - не подходит, если есть ограничения;
   - привязка к category/brand/product attributes.
3. Добавить FAQ только там, где ответы реально специфичны:
   - 3-6 вопросов;
   - без шаблонной воды;
   - FAQ должен быть видимым.
4. Добавить таблицу совместимости:
   - серия;
   - номинал;
   - полюсность;
   - тип монтажа;
   - напряжение;
   - совместимые аксессуары;
   - аналоги, если данные есть.
5. Добавить технические документы:
   - datasheet;
   - инструкция;
   - сертификат;
   - гарантийный документ;
   - PDF должен иметь понятное имя файла.
6. Усилить изображения:
   - главное фото товара;
   - фото маркировки;
   - фото упаковки;
   - фото применения или монтажа;
   - alt на основе названия, бренда, ключевой характеристики.
7. Добавить короткие видео для важных SKU:
   - обзор 30-90 секунд;
   - монтаж / подключение;
   - сравнение с аналогом.
8. Проверить Product schema:
   - `sku`, `mpn`, `gtin` при наличии;
   - `brand`;
   - `offers.price`, `priceCurrency`, `availability`, `url`;
   - `shippingDetails`;
   - `hasMerchantReturnPolicy`;
   - `aggregateRating` / `review` только при реальных отзывах.

### Методология контента для карточки

Структура верхней части:

1. H1: точное название товара.
2. Цена, наличие, CTA, доставка.
3. Короткий ответ.
4. Основные характеристики.
5. Фото/галерея.
6. Подойдет / не подойдет.
7. Характеристики и совместимость.
8. Описание.
9. FAQ.
10. Отзывы.
11. Похожие товары и статьи.

### Критерии приемки

- 80% топовых товарных SKU имеют уникальный короткий ответ.
- 50% топовых SKU имеют FAQ или совместимость.
- Product schema проходит Rich Results Test.
- Нет schema, которая не соответствует видимому контенту.
- CTR товарных страниц из GSC растет по prior-срезу.
- Конверсия product page не снижается после добавления контента.

### Цель

Превратить категории и whitelisted filter pages в понятные посадочные страницы для long-tail коммерческих запросов и AI-ответов.

### Текущее состояние

- Есть `AnswerBlock`.
- Есть category articles.
- `src/lib/direct-answers.ts` покрывает ограниченный набор категорий.

### Задачи

   - топ-30 категорий;
   - топ-50 quick-link страниц;
   - топ-20 частых сценариев выбора.
2. Для каждой категории добавить:
   - короткий ответ;
   - как выбрать;
   - основные параметры;
   - частые ошибки;
   - таблицу "параметр - что означает - как выбрать";
   - ссылки на релевантные quick links.
3. Для quick-link страницы добавить уникальный intro:
   - что именно отфильтровано;
   - кому подходит;
   - ключевой критерий выбора;
   - ссылка обратно на родительскую категорию.

   - сортировки;

   - произвольные фильтры;
   - внутренний поиск.
6. В sitemap включать только canonical category и whitelisted quick links.

### Методология выбора quick links

Quick-link можно индексировать, если выполняются все условия:

- есть поисковый спрос или бизнес-важность;
- страница имеет минимум 8-12 релевантных товаров или явно полезна при меньшем количестве;
- комбинация фильтров стабильна;
- есть уникальный intro и direct answer;
- URL не создает дубли с category / brand / search;
- страница может быть поддержана ассортиментом и наличием.

### Критерии приемки

- Топ-30 категорий имеют AnswerBlock.
- Топ-50 quick links имеют уникальный direct answer и self-canonical.
- Произвольные фильтры имеют `noindex` и canonical на категорию.
- В GSC нет массовых дублей по параметрам фильтров.
- Внутренние ссылки с категорий ведут на релевантные quick links.

## 15. Work Package 11: `llms.txt` и LLM-facing слой

### Цель

Поддерживать `llms.txt` как дополнительный навигационный файл, но не считать его ключевым фактором ранжирования.

### Правила

- Не строить стратегию вокруг `llms.txt`.
- Не тратить на него больше 5-10% SEO-времени.
- Хранить в нем только полезные ссылки:
  - основные категории;
  - guides;
  - правила покупки/доставки/возврата;
  - sitemap;
  - контакты.
- Не добавлять туда промо-текст, который не поддержан сайтом.
- Обновлять при крупных изменениях структуры сайта.

### Критерии приемки

- `public/llms.txt` актуален.
- В нем нет закрытых, тестовых или staging URL.
- Он не используется как замена sitemap, schema или нормального HTML-контента.

## 19. Риски и ограничения

- AI Overviews / AI Mode не гарантируют цитирование даже при идеальной оптимизации.
- Нельзя обещать попадание в AI-ответы как результат отдельной разметки.
- `llms.txt` не является заменой индексируемому HTML, schema и sitemap.
- Shopping-запросы могут чаще обрабатываться Google Shopping features, а не AI Overviews.
- Массово сгенерированный слабый контент ухудшит качество сайта.
- Fake reviews, fake FAQ и hidden text недопустимы.
- Переиндексация может занять недели.

## 20. Definition of Done

Работа по SEO / AI усилению считается принятой, если:

- изменения внедрены без нарушения правил Next.js 16 и Prisma;
- product/category/guide templates проходят technical QA;
- sitemap, robots, canonical, hreflang корректны;
- schema соответствует видимому контенту;
- Merchant feed валиден;
- в GSC нет новых массовых ошибок индексации;
- есть baseline и регулярный отчет;
- для каждого внедренного блока есть измеримый KPI;
- контент помогает пользователю выбрать товар, а не только имитирует SEO.

## 21. Практический чеклист для каждого нового SEO-блока

Перед публикацией новой страницы или блока проверить:

- Пользователь за 10 секунд понимает, что это и зачем.
- Есть короткий прямой ответ.
- Есть реальные характеристики, ограничения или сравнения.
- Есть внутренние ссылки на релевантные товары/категории.
- Есть schema только для видимого контента.
- Canonical корректный.
- Страница индексируется только если она уникальна и полезна.
- Нет скрытого текста.
- Нет placeholder-данных.
- Mobile layout не ломается.
- CTA покупки не теряется из-за SEO-контента.

## 23. Финальная формула Alpha 1.1

Elektronom должен выглядеть для Google, AI-систем и пользователя как технический экспертный магазин:

- каталог с точными товарами;
- категории с понятной методикой выбора;
- карточки с характеристиками, совместимостью и доказательствами;
- гайды, которые отвечают на реальные вопросы;
- Merchant feed, который совпадает с сайтом;
- бренд, которому можно доверять;
- аналитика, которая показывает, что именно работает.

Это и есть практическая SEO / AI / GEO оптимизация для Project Alpha V1.1: не отдельный "AI-слой", а усиление каждой точки, где пользователь, поисковик и AI-модель пытаются понять, почему этот товар, эта категория и этот магазин заслуживают доверия.
