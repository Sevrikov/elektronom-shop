## 1. Зачем это нужно

Предыдущий MVP калькулятора строит схему по фиксированным чекбоксам: бойлер, духовка, варочная поверхность, стиральная машина и т.д. Этого недостаточно.

В реальной жизни пользователь может собирать:

- квартирный щит;
- щит дома;
- щит гаража/мастерской;
- резервное питание с генератором;
- инвертор + аккумуляторы;
- несколько групп освещения;
- тёплый пол;
- зарядку электромобиля;
- насосы;
- сервер/роутер/видеонаблюдение;
- мастерскую со станками;
- гибридную схему с АВР, УЗИП, реле напряжения и приоритетными нагрузками.

Поэтому нужен не только калькулятор, а схемостроитель, где пользователь добавляет свои потребители, а система постоянно проверяет норму, совместимость и риски.

## 2. Главный принцип

Система должна работать так:

```text
Пользователь добавляет потребитель
  -> движок считает нагрузку
  -> NormGuard проверяет безопасность
  -> CatalogMatcher ищет допустимые компоненты
  -> SchemeBuilder показывает схему
  -> AI предлагает помощь, если видит сложность/риск
```

AI не является источником нормы. AI объясняет, спрашивает, предлагает варианты, но все запреты и разрешения приходят из `NormGuard`.

## 3. Пользовательские потребители

### 3.1 Что должен уметь пользователь

Пользователь должен иметь кнопку:

```text
+ Добавить потребитель
```

После нажатия открывается форма:

- название;
- помещение;
- тип потребителя;
- мощность, Вт или кВт;
- фаза: 1ф / 3ф;
- режим работы: постоянный / кратковременный / пусковой;
- влажная зона: да/нет;
- критическая нагрузка: да/нет;
- нужно резервное питание: да/нет;
- нужна отдельная линия: да/нет;
- длина трассы;
- желаемый способ подключения: розетка / стационарно / клеммная коробка / щит;
- комментарий пользователя.

## 4. Автоматическое определение сложности

Система должна считать `projectComplexityScore`.

Факторы сложности:

- больше 8 линий;
- есть 3-фазные нагрузки;
- есть генератор/инвертор/UPS;
- есть АВР;
- есть алюминиевая проводка;
- есть Al/Cu переходы;
- есть мокрые зоны;
- есть наружные линии;
- есть EV charger;
- есть насос/компрессор/сварка с пусковыми токами;
- есть неясные данные: unknown PE, unknown neutral, unknown source bonding;
- пользователь пытается вручную поставить компонент с `P0_BLOCK`.

```ts
interface ComplexityResult {
  score: number
  level: 'simple' | 'medium' | 'complex' | 'expert-only'
  reasons: string[]
  aiShouldOfferHelp: boolean
  electricianReviewRequired: boolean
}
```

## 5. Когда AI должен сам предлагать помощь

AI-помощник не должен быть навязчивым, но обязан появляться в опасных/сложных моментах.

### 5.1 Триггеры AI-помощи

AI предлагает помощь, если:

1. Пользователь добавил генератор, инвертор, UPS или АВР.
2. Пользователь выбрал 3P АВР при наличии нейтрали/однофазных нагрузок.
3. Пользователь указал алюминиевую проводку или Al/Cu переход.
4. Есть `P0_BLOCK`.
5. Есть больше 3 предупреждений `P1_WARNING`.
6. Пользователь добавил 3-фазный потребитель.
7. Вводной автомат/мощность не хватает под выбранные нагрузки.
8. Падение напряжения выше допустимого.
9. Пользователь вручную заменил компонент на несовместимый.
10. Схема стала `complex` или `expert-only`.

### 5.2 Как AI предлагает помощь

Не модальное окно на весь экран. Нужна мягкая подсказка рядом со схемой:

```text
Вижу, что вы добавили генератор и АВР. Здесь важно проверить нейтраль и заземление. Помочь выбрать безопасную схему?
[Да, помоги] [Нет, продолжу сам]
```

Для опасных случаев:

```text
Эта замена заблокирована: выбранный АВР 3P не переключает нейтраль, а источник похож на separately derived system. Могу показать безопасные варианты.
[Показать варианты] [Объяснить проще]
```

### 5.3 Состояния AI-помощника

- `idle`: спокойно присутствует;
- `watching`: видит изменения схемы;
- `suggesting`: предлагает помощь;
- `explaining`: объясняет проблему;
- `comparing`: показывает сравнение старого и нового решения;
- `blocked`: сообщает, что действие запрещено NormGuard;
- `handoff`: предлагает обратиться к электрику/инженеру.

## 6. AI не должен иметь права обходить нормы

Запрещено:

- AI не может снять `P0_BLOCK`.
- AI не может добавить заблокированный товар в корзину.
- AI не может сказать “можно так оставить”, если `NormGuard` запрещает.
- AI не может выдумать характеристики товара.
- AI не может считать товар допустимым без `datasheetUrl` или проверенного `EngineeringSpec`.

Разрешено:

- объяснить проблему простым языком;
- задать уточняющий вопрос;
- предложить допустимые альтернативы;
- показать, какие данные нужно ввести;
- подсказать, почему нужен электрик.

## 7. Сценарии сложных схем

### 7.1 Генератор + АВР

Поля:

- тип генератора;
- фаза;
- мощность;
- neutral mode: floating / bonded / unknown;
- есть ли заземлитель;
- какие нагрузки резервировать;
- нужен ли автоматический запуск;
- тип АВР: manual / motorized / automatic;
- neutral switching: none / solid / switched / overlapping.

NormGuard должен:

- блокировать 3P АВР, если нужна коммутация нейтрали;
- предупреждать при unknown neutral;
- требовать 4P/switched neutral для separately derived source, если нет подтверждённой схемы;
- проверять ток АВР;
- проверять фазность;
- проверять приоритетные нагрузки.

### 7.2 Инвертор + аккумуляторы

Поля:

- мощность инвертора;
- тип: off-grid / hybrid / backup;
- neutral bonding;
- bypass;
- battery voltage;
- battery capacity;
- резервируемые линии;
- наличие УЗО/диф после инвертора.

AI должен предложить помощь почти всегда, потому что сценарий сложный.

### 7.3 Алюминиевая старая проводка

Поля:

- есть ли Al проводка;
- где она: ввод / группы / отдельные линии;
- сечение;
- тип жилы;
- планируется ли переход на Cu;
- тип соединения.

NormGuard должен:

- блокировать обычные Cu-only клеммы;
- требовать Al/Cu совместимый соединитель;
- требовать пасту/смазку, если производитель требует;
- требовать ручную проверку старых соединений.

### 7.4 Мастерская/гараж

Поля:

- станки;
- сварка;
- компрессор;
- насос;
- пусковые токи;
- наружные розетки;
- влажность/пыль.

NormGuard:

- проверяет пусковые токи;
- предлагает отдельные линии;
- предупреждает по падению напряжения;
- требует подходящий IP для наружных точек;
- предлагает 3-фазный ввод при необходимости.

## 8. UX схемостроителя

### 8.1 Основные зоны интерфейса

1. Левая панель: объект и потребители.
2. Центр: визуальная схема.
3. Правая панель: BOM, совместимость, NormGuard.
4. Нижняя панель: итоговая стоимость, заблокированные позиции, экспорт.
5. AI-помощник: плавающий персонаж/панель, привязанная к текущей проблеме.

### 8.2 Добавление потребителя

Пользователь может:

- выбрать шаблон;
- ввести вручную;
- спросить AI: “Добавь насос 1.1 кВт в гараж”;
- импортировать список потребителей из текста.

### 8.3 Визуальная схема

Схема должна показывать:

- ввод;
- реле напряжения/УЗИП;
- АВР/инвертор, если есть;
- УЗО/диф;
- автоматы;
- линии;
- потребители;
- цветной статус каждой ветки.

Компонент с проблемой должен иметь значок:

- красный: запрещено;
- жёлтый: требует внимания;
- серый: нет данных;
- зелёный: проверено.

## 9. Данные для каталога

Каждый инженерный товар должен иметь `EngineeringSpec`.

Минимум:

- роль товара;
- технические характеристики;
- ссылки на datasheet/manual/catalog;
- источник проверки;
- дата проверки;
- уровень доверия;
- совместимость материалов;
- совместимость фаз/нейтрали;
- совместимость с типами схем.

Для сложных товаров (АВР, инверторы, УЗО, дифы, клеммы Al/Cu) без `EngineeringSpec` товар нельзя считать допустимым.

## 10. API для AI

AI должен получать не весь сырой проект, а структурированный безопасный контекст:

```ts
interface AssistantEngineeringContext {
  projectSummary: string
  loads: CustomLoadInput[]
  normIssues: NormIssue[]
  blockedActions: string[]
  allowedAlternatives: ProductAlternative[]
  missingDataQuestions: string[]
  complexity: ComplexityResult
}
```

AI должен возвращать:

```ts
interface AssistantEngineeringReply {
  message: string
  suggestedActions: Array<
    | { type: 'ask-question'; question: string }
    | { type: 'show-alternatives'; targetId: string }
    | { type: 'apply-safe-change'; changeId: string }
    | { type: 'explain-issue'; issueId: string }
    | { type: 'recommend-electrician-review' }
  >
}
```

## 11. Acceptance Criteria

1. Пользователь может добавить произвольный потребитель вручную.
2. Пользователь может удалить/редактировать потребитель.
3. Схема пересчитывается после каждого изменения.
4. NormGuard пересчитывается после каждого изменения.
5. Если появляется `P0_BLOCK`, кнопка финального добавления BOM в корзину блокируется.
6. AI предлагает помощь при генераторе/АВР/инверторе/Al/Cu/мокрых зонах.
7. AI не может снять блокировку.
8. Пользователь видит, какая именно линия или компонент проблемный.
9. Пользователь видит, какие данные отсутствуют.
10. Пользователь видит допустимые альтернативы из каталога.
11. Товар без engineering spec не считается безопасным для критической роли.
12. Сложный проект получает метку `expert-only`.

## 13. Итог

Схемостроитель должен стать не формой с чекбоксами, а инженерным рабочим столом:

- пользователь добавляет свои реальные потребители;
- система считает;
- NormGuard запрещает опасное;
- каталог даёт только проверенные товары;
- AI помогает в сложных местах, но не заменяет норму и электрика.
