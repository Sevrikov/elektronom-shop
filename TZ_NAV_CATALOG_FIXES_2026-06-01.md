> Дата: 2026-06-01. Источник: **ручное сканирование живой сборки** (preview, через авторизованную сессию браузера): `…vercel.app/ru`. Защищён (HTTP 401 для внешнего fetch) — сканировано через браузер.
> Правила: `MASTER_CONTEXT`+addendum, §0 anti-regression, `lint`/`tsc`/`build` зелёные.

## 🔴 КРИТИЧНО — каталог не показывает товары (browse сломан)
**Симптом (воспроизведено):** ВСЕ проверенные категории рендерят страницу (правильный H1/title/SEO, сортировка, подкатегории, фасет-сайдбар), но листинг — **«Найдено 0 товаров»**, 0 карточек:

| URL | В меню (счётчик) | Факт на странице |
|---|---|---|
| `/ru/catalog/elektryka` | **3816** | **Найдено 0 товаров** |
| `/ru/catalog/videosposterezhennya` | **748** | **Найдено 0 товаров** |
| `/ru/catalog/avtomatychni-vymykachi` | (без счётчика) | 0 товаров |
| `/ru/catalog/usb-khaby` | 4 | 0 товаров |

→ **Через навигацию каталога нельзя дойти до товаров.** Товары существуют (БД 11 916 активных; страницы `/product/...` и «ТОП ПРОДАЖ» на главной работают) — но **не обнаруживаются через категории**. Это бьёт по UX, конверсии и SEO (категории — ключевые посадочные).

### Гипотезы причины (для разработчика — проверить)
1. **Листинг фильтрует по прямому слагу категории, без поддерева.** Счётчики в меню (3816) = агрегат по поддереву (категория + потомки), а `getFilteredProducts`/`getCategoryProductsForFacets` берут `where: { category: { slug } }` (только прямые) → у родительских категорий 0 (товары лежат в подкатегориях). **Фикс:** собирать ID категории + всех потомков (рекурсия по `parentId`/дерево) и фильтровать `categoryId IN (поддерево)` — и в листинге, и в фасетах.
2. **ИЛИ рассинхрон таксономии:** товары импортированы в категории, чьи слаги не совпадают со слагами в дереве навигации; меню ссылается на категории без прямых товаров.
3. **ИЛИ регресс в `getFilteredProducts`** после правок catalog-страницы (canonical/`connection()` дизайнерские изменения) — проверить, что where-условие не сломалось.
- **Диагностика:** `/ru/catalog/elektryka` → «Найдено 0», но сайдбар показывает подкатегории (Каучуковые разъемы, Электроизмерительные приборы…) → товары — в детях. Подтверждает гипотезу №1.

### Задачи
- **T-CAT-FIX-1 🔴** Листинг категории включает поддерево: собрать `categoryIds = [self, ...descendants]`, в `queries/products.ts:getFilteredProducts` (и `getCategoryProductsForFacets`) фильтровать `categoryId: { in: categoryIds }`.
  - **Приёмка:** `/catalog/elektryka` показывает товары (≈3816, с пагинацией); счётчик «Найдено N» совпадает со счётчиком меню; фасеты считаются по поддереву.
- **T-CAT-FIX-2** Тест-регресс (Стадия 1 E1.1): для родительской категории листинг > 0 и = агрегату.

## 🟡 Таксономия — дубли и рассинхрон слагов
В боковом меню/мегаменю есть дубли и параллельные слаги (часть — из `catalog-filter-config.ts`/`catalog-mega-menu.ts`, не совпадают с деревом БД):
- Дубли: `power-bank`#21 ↔ `poverbanky`#14; `heneratory`#7 ↔ `heneratory-1`#7; `kabeli-droty`#154 ↔ `kabeli-i-roz-yemy`#41; `tepla-pidloha` ↔ `tepla-pidloha-zubr-dc`.
- Параллельные слаги без счётчика (config-навигация, не дерево БД): `elektrika` (лат.) ↔ `elektryka`, `dbzh`, `rozetky-ta-vymykachi`, `kabel-ta-provid`, `osvitlennya-led`, `shchyty-elektrychni`, `instrument-ruchnyy`, `pzv-ta-dyf-avtomaty`, `motornye-masla`, `akumulyatory` — после T-CAT-FIX-1 проверить, что они либо мапятся на реальные категории, либо убраны.
- **T-TAX-1 🟡** Свести навигацию к **единому источнику** — дереву категорий БД; убрать дубли/мёртвые слаги из mega-menu/filter-config; настроить редиректы со старых слагов на канонические (301).
  - **Приёмка:** каждый пункт меню ведёт на существующую непустую категорию; нет двух слагов на одну сущность.
