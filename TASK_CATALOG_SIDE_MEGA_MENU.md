# ТЗ: боковое выпадающее меню каталога / Mega Menu

Дата: 2026-05-24  
Проект: Elektronom  
Цель: заменить простое меню каталога на удобное боковое mega menu, где пользователь сразу видит категории, подкатегории, популярные группы/товары и контекстную промо-зону.

## 1. Общая идея

При клике на кнопку `Каталог` / `Меню каталогу` открывается широкий выпадающий слой под шапкой сайта. Остальная часть сайта затемняется полупрозрачным overlay, но сама шапка и меню остаются активными и читаемыми.

Меню должно быть похоже по логике на референс: слева список основных категорий, в центре подкатегории выбранной категории, справа популярные запросы/группы/товары, ещё правее или в отдельном блоке промо-баннер выбранной категории.

Это не модальное окно. Это навигационный dropdown/mega menu, привязанный к шапке.

## 2. Поведение

### Открытие

- Открывается по клику на кнопку `Каталог` в desktop-header.
- На desktop можно дополнительно поддержать hover, но базовое и обязательное поведение — click toggle.
- Повторный клик по кнопке закрывает меню.
- Клик вне меню закрывает меню.
- Нажатие `Escape` закрывает меню.
- При переходе по ссылке меню закрывается.

### Затемнение сайта

- При открытом меню весь контент ниже header затемняется overlay.
- Overlay должен быть мягким: примерно `bg-black/35` или токенизированный аналог.
- Overlay не должен перекрывать само меню.
- Header остаётся поверх overlay.
- Запрещено затемнять само меню до потери читаемости.

### Скролл

- Страница под меню не должна хаотично прокручиваться при наведении на меню.
- Если список категорий/подкатегорий длинный, скролл должен быть внутри меню.
- На desktop высота меню ограничена: `calc(100vh - headerHeight - 16px)`.
- Внутренние колонки могут иметь `overflow-y-auto`.

## 3. Структура меню на desktop

Рекомендуемая сетка:

```text
┌────────────────┬─────────────────────────────┬──────────────────────┬────────────────────┐
│ Категории      │ Подкатегории / группы       │ Популярні запити     │ Промо категории    │
│ 300-340px      │ 1fr, 2 колонки              │ 260-300px            │ 280-340px          │
└────────────────┴─────────────────────────────┴──────────────────────┴────────────────────┘
```

### Колонка 1: основные категории

Показывать список основных категорий:

- иконка категории;
- название;
- стрелка вправо;
- активное состояние выбранной категории;
- количество товаров опционально, если есть в данных.

Пример пунктов:

- Знижки та акції
- Енергозабезпечення
- Відеонагляд
- Домофони
- Контроль доступу
- Охоронна сигналізація
- Кабельна продукція
- Мережеве обладнання
- Розумний будинок
- Електромонтажне обладнання

Активная категория подсвечивается `bg-surface-alt` / светло-синим акцентом, стрелка становится заметнее.

### Колонка 2: подкатегории выбранной категории

Для активной категории показывать сгруппированные подкатегории в 2 колонки.

Пример для `Енергозабезпечення`:

- Комплекти резервного живлення
- Акумулятори для інвертора
- Джерела безперебійного живлення
  - ДБЖ для роутерів
  - ДБЖ 12/24V
  - ДБЖ UPS 220V
- Генератори
- Автономне живлення
  - Системи накопичення енергії
  - Промислові системи накопичення енергії
  - Аксесуари для систем накопичення енергії
- Інвертори
- Акумулятори для ДБЖ
- Блоки живлення
  - Блоки живлення 12/24/48V
  - Зарядні пристрої для акумуляторів
  - Зарядні пристрої USB
- Портативні зарядні станції
- Сонячна енергетика
  - Інвертори для сонячних панелей
  - Контролери заряду сонячних панелей
  - Сонячні панелі
  - Оптимізатори потужності сонячних панелей
  - Кріплення для сонячних панелей

Группы должны быть кликабельными, подгруппы тоже. Не делать просто статический текст.

### Колонка 3: популярные запросы / группы / товары

Показывать контекстные популярные элементы для активной категории:

- маленькое изображение 40-48px;
- название группы/товара;
- ссылка на категорию, фильтр или товар;
- опционально цена/лейбл, если это конкретный товар.

Пример для `Енергозабезпечення`:

- Міні ДБЖ для роутера
- Зарядні станції
- Інвертор + батарея
- Акумулятори LiFePO4
- Акумулятори GEL
- Акумулятори AGM
- Інверторні генератори
- Генератори бензинові
- Генератори дизельні

Важно: это должны быть реальные ссылки, а не декоративный список.

### Колонка 4: промо-зона категории

Промо-блок должен меняться в зависимости от активной категории.

Для `Енергозабезпечення`:

- заголовок: `Системи енергонезалежності`
- подзаголовок: короткая польза/оффер;
- изображение товара/комплекта;
- CTA: `Детальніше` или `Перейти до добірки`;
- ссылка на категорию/landing/подборку.

Если для категории нет промо-данных, показывать аккуратный fallback:

- светлый технический фон;
- название категории;
- CTA `Перейти до категорії`;
- без пустых серых заглушек.

## 4. Данные и архитектура

Не хардкодить меню в JSX как огромный статический блок.

Нужно сделать нормальную структуру данных:

```ts
type MegaMenuCategory = {
  id: string
  slug: string
  title: string
  icon?: string
  productCount?: number
  groups: MegaMenuGroup[]
  popular?: MegaMenuPopularItem[]
  promo?: MegaMenuPromo
}
```

Источник данных:

- если есть категории в БД — строить меню из существующих категорий + curated-настроек для popular/promo;
- если пока нет полноценной структуры — создать временный config-файл, например `src/config/catalog-mega-menu.ts`, но с понятной схемой и TODO для подключения к БД.

Обязательные правила проекта:

- Next.js 16: не добавлять route config вроде `revalidate` / `dynamic`;
- server-side данные получать через server functions с `'use cache'`, `cacheLife`, `cacheTag`, если используется запрос к БД;
- Prisma-запросы только через `@/lib/prisma`;
- Tailwind v4: без inline `style={{...}}`, только классы и токены из `globals.css`;
- интерактивность вынести в маленький client component, например `CatalogMegaMenuClient`.

## 5. Компоненты

Рекомендуемая структура:

```text
src/components/layout/catalog-mega-menu.tsx
src/components/layout/catalog-mega-menu-client.tsx
src/config/catalog-mega-menu.ts
```

Или, если в проекте уже есть другая структура layout/header, вписать туда без ломки существующей архитектуры.

Компонент должен интегрироваться с текущим header:

- кнопка `Каталог` открывает меню;
- desktop nav не ломается;
- mobile nav не ломается;
- поиск в header остаётся рабочим;
- корзина/аккаунт/wishlist остаются поверх или корректно закрывают меню при клике.

## 6. Mobile / tablet

На mobile меню не должно пытаться втиснуть 4 колонки.

Поведение:

- открывать как fullscreen drawer или bottom/side drawer;
- первый экран: список основных категорий;
- клик по категории открывает второй уровень с кнопкой `Назад`;
- популярные товары/группы показывать ниже подкатегорий;
- промо-блок можно показывать внизу или скрывать, если не помещается.

Минимальные размеры для проверки:

- 390px mobile;
- 768px tablet;
- 1024px small desktop;
- 1440px desktop.

## 7. UX и доступность

- `aria-expanded` на кнопке каталога.
- `aria-controls` для меню.
- `role="navigation"` или понятная семантика.
- Закрытие по `Escape`.
- Фокус не должен теряться.
- Активный пункт категории должен быть видимым.
- Все ссылки должны иметь нормальные `href`.
- Не должно быть layout shift при открытии/закрытии.

## 8. Визуальный стиль

Меню должно соответствовать текущему стилю Elektronom:

- фон меню: `bg-surface-white`;
- фон страницы под overlay: затемнение;
- радиусы максимум 8px, кроме если текущий дизайн-системный компонент уже использует другой радиус;
- акцент: синий Elektronom;
- текст: `text-text-primary`, вторичный `text-text-muted`;
- границы: `border-border`;
- без тяжёлых градиентов и декоративных пятен;
- изображения товаров должны быть реальными или из текущего каталога/Cloudinary, не случайные stock-заглушки.

## 9. Acceptance criteria

Задача считается готовой, если:

1. По клику на `Каталог` открывается mega menu.
2. Остальная страница затемняется overlay.
3. При наведении/клике на категорию меняются подкатегории, популярные группы/товары и промо-блок.
4. Все пункты меню кликабельны и ведут на реальные URL.
5. На desktop меню не вылезает за экран и имеет внутренний скролл при длинных списках.
6. На mobile меню работает как drawer/многоуровневый список.
7. `Escape`, клик вне меню и переход по ссылке закрывают меню.
8. Нет inline styles в новых компонентах.
9. Нет хардкода украинского/русского текста внутри TSX, если текст должен локализоваться.
10. Команды проходят:

```powershell
npm.cmd run lint
npx.cmd tsc --noEmit
npm.cmd run build
```

11. Разработчик прикладывает screenshots:

```text
delivery/visual-checks/catalog-mega-menu-desktop-open.png
delivery/visual-checks/catalog-mega-menu-desktop-energy.png
delivery/visual-checks/catalog-mega-menu-mobile-level-1.png
delivery/visual-checks/catalog-mega-menu-mobile-level-2.png
```

## 10. Приоритет реализации

### Sprint 1: desktop MVP

- открыть/закрыть меню;
- overlay;
- 3-4 колонки;
- активная категория;
- подкатегории;
- популярные группы;
- промо-блок;
- реальные ссылки.

### Sprint 2: mobile UX

- drawer;
- переходы между уровнями;
- корректный back;
- проверка 390px/768px.

### Sprint 3: data integration

- подключить категории/подкатегории к БД;
- popular/promo вынести в управляемый config или админку;
- добавить изображения из Cloudinary/товарных медиа.

## 11. Что не делать

- Не делать меню картинкой.
- Не делать статический HTML без реальных ссылок.
- Не ломать текущую шапку, поиск, корзину и мобильную навигацию.
- Не добавлять новые UI-библиотеки без необходимости.
- Не использовать inline styles.
- Не создавать `middleware.ts`.
- Не добавлять route config в Next.js pages/layouts.
