> Дата: 2026-06-01. Финальная стадия `TZ_ENTERPRISE_ROADMAP`. Цель: органический рост, повторные продажи, бренд-авторитет — закрепить статус «один из лучших в сегменте».
> **Предусловие:** Стадии 1–3 закрыты (observability/GA4, очереди/данные заказов, RAG/эмбеддинги товаров).
> Правила: `MASTER_CONTEXT`+addendum, §0 anti-regression, без `any`. Schema-изменения (Author и др.) — addendum к §6.
> Источники механики: `TZ_SEO_TOP10` (WP-1..13 — не дублируем, ссылаемся), `_reversa_sdd/vision-next-level.md` (Ставки 4, 6).
> **Exit/KPI:** ТОП-10 по ядру; dwell time 120+с; рост LTV/повторных; Knowledge Panel; стабильные цитаты в AI Overviews.

## E4.1 — Контент-хаб / гайды 🟡 (двойное назначение: SEO + корпус RAG)
База есть: `(shop)/blog`, `lib/articles`. Масштабировать.

### Задачи
- **Контент-модель:** перейти от файловых `articles` к модели (`Article`/`Guide`) **или переиспользовать `TechnicalDocument`** — чтобы гайды одновременно были **корпусом RAG** (E3.1 эмбеддинги). Редакторский workflow в admin (draft/publish, автор, категория).
- **AEO-формат** каждой статьи: H1-интент, H2/H3-вопросы, **Direct Answer 40–80 слов**, FAQ, таблицы; через Content Factory (см. `TZ_SEO_TOP10` WP-3).
- **Темы** под интенты/калькуляторы (E3.1.6): «як підібрати кабель за потужністю», «який автомат на бойлер», «розрахунок ДБЖ». Каждая статья → внутренние ссылки на категории/товары (силос).
- **Связка с RAG:** публикация статьи → job `assistant/embed-docs` (E2.6) → ассистент цитирует её.
- **Приёмка:** темп ≥1–2 гайда/нед; индексируются (sitemap уже включает `/blog`); ассистент цитирует гайды как источник; есть FAQ/HowTo-разметка.

## E4.2 — SEO-авторитет 🟡 (исполнение `TZ_SEO_TOP10`)
> Механика — в `TZ_SEO_TOP10`. Здесь — что довести до «авторитета».

### Задачи
- **Программные фасет-лендинги (WP-2):** sitemap уже включает quick-links — наполнить их уникальным контентом (Direct Answer + подборки) и H1/meta (`catalog/[slug]` уже умеет self-canonical/index для whitelisted).
- **Schema-граф (WP-4):** Organization (есть — заменить NAP-заглушки реальными), **FAQPage**, **HowTo** (гайды E4.1), **Person/Author** (E-E-A-T), BreadcrumbList.
- **E-E-A-T (WP-6):** модель `Author` (имя/должность/`hasCredential`/соцсети) + карточки в гайдах + Person-schema; Trust-страницы (`about`/`privacy`/`terms` реальными данными); бейдж «перевірена покупка» (`verifiedPurchase`).
- **Бренд-сущность (WP-8):** Wikidata, **Google Knowledge Panel**, GBP, `sameAs` (реальные соцсети), упоминания бренда (linkless).
- **Линкбилдинг (WP-9):** микс Outreach/Guest/Crowd/Digital PR, 5–15 кач. ссылок/мес (off-site, не код).
- **Локальное SEO (WP-12):** GBP, NAP-консистентность, `LocalBusiness` schema.
- **AI-SEO:** оптимизация под цитирование в AI Overviews (Princeton-методы: статистика/цитаты/источники — WP-3).
- **Приёмка:** Rich Results/Merchant тесты зелёные; появляется Knowledge Panel; рост органики и брендовых запросов; цитаты в AIO (трекинг WP-10).

## E4.3 — Рекомендации / персонализация 🟡
### Задачи
- **Recently viewed** (cookie/localStorage + сервер-рендер блока).
- **Похожие / «та же серия»** — уже есть `getSimilarProducts`/`getSameSeriesProducts` (модуль product) → вынести в виджеты на PDP/категории.
- **«С этим покупают»** — матрица ко-покупок из `OrderItem` (batch-job E2.6, пересчёт ночью); виджет на PDP/в корзине.
- **AI-рекомендации** — переиспользовать **product-эмбеддинги** (pgvector E3.1): «похожие по характеристикам/применению».
- **Персонализация** — переупорядочивание выдачи/главной по истории (recently viewed/купленному); осторожно с кэшем (`'use cache'` — персональные блоки вне кэша/через Suspense).
- `lib/recommendations/` — сервис; не доверять клиенту, считать на сервере.
- **Приёмка:** виджеты рекомендаций на PDP/главной/в корзине; A/B-замеренный рост AOV/CTR карточек.

## E4.4 — Аналитика спроса / маржи (BI) 🟡
### Задачи
- **GA4** — события/конверсии/воронки (достроить с E1.3): просмотры, add-to-cart, checkout, покупка, dwell.
- **Маржа/оборачиваемость** — продуктизировать идею `analyze-products.ts`: дашборд из `Order/OrderItem/Product(costPrice)/SupplierInventory` — маржа, velocity, топ/аутсайдеры, **dead stock**, ABC-анализ.
- **Прогноз спроса** (базовый) + **эффективность поставщиков** (сроки/наличие из `SupplierInventory`).
- Реализация: дашборд в admin **или** внешний BI (Metabase/Looker Studio) на реплике/экспорте; тяжёлые агрегаты — job (E2.6), не на запросе.
- **Приёмка:** управленческие решения на данных; видны маржа/velocity/dead-stock; отчёт по поставщикам.

## E4.5 — CRO / культура экспериментов 🟢
### Задачи
- **Инфраструктура A/B** — feature-flags + эксперименты (PostHog / GrowthBook / Statsig / Vercel Flags). См. подход `/ab-test-setup`.
- **Бэклог экспериментов** (ICE-приоритизация); системные тесты ключевых воронок: PDP-CTA, checkout-шаги, signup, поиск, рекомендации.
- Метрики/значимость — через аналитику (E4.4/E1.3).
- **Приёмка:** регулярные эксперименты с статистической значимостью; решения по данным, а не по вкусу; растёт конверсия/AOV подтверждённо.
